# 4-1_LangChain 서비스 개발
## Post-training(Instruction-tuning, RLHF)
Pre-traininng(사전 학습): 방대한 텍스트 데이터를 통해 언어 패턴과 지식을 배우는 단계
다음 단어 예측(Next Token Prediction)
질문에 대한 답을 하지는 않음

Post-training(사후 학습): 사람이 원하는 방식으로 대화하고, 안전하고 유용하게 만드는 단계 
유저의 의도를 파악하고 답변을 출력

사전 학습 후 파인 튜닝 진행 
파인 튜닝: 사전학습된 기존 모델에 특정 작업에 맞게 추가로 학습
Instruction-tuning: 언어모델이 사람이 내린 지시문을 따르도록 학습. 정답 레이블이 필요.
다양한 태스크에서 지시문-응답 쌍을 모아 파인 튜닝 -> 학습하지 않은 새로운 태스크에서 평가 진행 
지시문, 입력, 출력을 언어모델로부터 생성 
pre-training에 비해 많은 데이터가 필요하지 않음 
MMLU(Massive Multitask Language undrestanding): Instruction-tuned된 언어 모델 평가 벤치마크 
Instruction-tuning의 한계
1. 개방형/창의적 생성 같은 테스크에는 정답 없음
2. 언어 모델링은 모든 토큰 레벨의 오류를 동일하게 취급하지만 어떤 오류는 다른 오류보다 심하게 적용
3. 사람이 만든 답변이 최적이 아닐 수 있음 

RLHF(Reinforcement Learning from Human Feedback)
Human-in-the-loop ML
데이터 수집 및 감독 학습 -> 비교 데이터 수집 및 보상 모델 학습 -> 강화학습(PPO)로 정책 최적화
인간의 선호도는 일관성이 없고 기준 어긋남 -> 점수 대신 응답을 비교해서 보상 모델 학습 
ChatGPT: Instruction-tuning + RLHF
리워드 모델링의 한계점: 리워드 해킹(인간의 선호도는 일관성이 부족함), 환각 문제

DPO(Direct Preference Optimizaion): RLHF에서 RL(강화학습) 제거. 사람이 비교한 선호 데이터를 이용해 언어 모델의 확률 분포를 직접 조정함. 보상 모델과 PPO 없이도 높은 성능을 달성 
RLVR(Leinforcement Leargning with Verifiable REward): RLHF에서 수학처럼 답이 분명한 문제들은 정답 여부로 리워드 부여

## Retrival-augmented Language Models(Information Retrieval, RAG)
Retrival-augmented LM: 추론 시 외부 데이터 저장소를 불러와 활용하는 언어 모델
구성 요소: datastore, Query, Index, Language Model 
datestore: 가공되지 않은 대규모 텍스트 코퍼스. 라벨링되지 않음. 구조화 안됨
쿼리: 검색 질의 / Retrieval input. 언어모델의 질의(input)과 같아야 하는 것은 아님 
인덱스: 문서나 단락을 체계적으로 정리하여 더 쉽게 찾을 수 있도록 한 것
각 정보 검색(Information Retrieval) 메서드는 인덱싱 과정에서 구축된 인덱스를 활용하여 쿼리와 관련 있는 정보를 식별함. 
검색(Retrieval): datastore에 있는 수 많은 정보 중에서 주어진 쿼리와 가장 관련성이 높은 정보를 찾아내는 과정
 
Retrieval-augmented Generation(RAG): 사용자의 질문에 답하기 위해, datastore에서 관련 정보를 검색해와서 이를 언어모델에 생성 단계에 함께 활용하도록 함 

Information Retrieval
검색 질의와 가장 관련성 높은 정보 제공 
정보 검색(IR): 사용자의 질의(쿼리)에 맞는 정보를 대규모 데이터에서 찾아 제공하는 과정
활용: 웹 서치 & 아이템 서치, 추천 서비스 
Retriever: 사용자의 질의(쿼리)에 맞는 후보 문서를 저장소에서 찾아오는 모듈. RAG에세서 첫 단계 역할. Sparse Retriever와 Dense Retriever 두 가지 종류
Sparse Retriever: 어휘적 유사도 기반. 쿼리와 문서 간의 정확한 용어 일치(어휘적 유사도)에 기반
Sparse Retriever - TF-IDF: 문서 내 특정 단어의 중요도를 나타내는 가중치 방식
TF(Term Frequency): 단어가 문서에 얼마나 자주 등장하는지. 자주 등장하는 단어는 중요.
IDF(Inverse Document Frequency): 단어가 전체 코퍼스에서 얼마나 드물게 등장하는지. 너무 많은 문서에서 등장하는 단어는 덜 중요함. 예)"this, is, and"
Sparse Retriever 장점
- 단순성: 구현과 이해 쉬움 
- 효율성: inverted index 구조로 빠른 검색
- 투명성: 검색 결과 해석 가능
Sparse Retriever 단점
- 제한된 의미 이해. 유의어끼리 매칭 안됨

Dense Retriever: 의미적 유사도 기반. 쿼리와 문서를 표현하기 위해 dense vector(임베딩)으로 의미적 유사도에 기반 
Dense Retriever - Bi-encoder: Bi-encoder retriever는 대조 학습을 통해 학습. 쿼리가 긍정적인 문서와 가깝게 유지되도록 하고 부정적인 문서에서는 물어지도록 유도 
Dense Retriever - cross-encoder: Cross-encoder 아키텍처가 두 개의 텍스트를 하나의 시퀀스로 결합. self-attention을 통해 모든 쿼리와 문서 토큰이 상호작용해서 Bi0encoder보다 정확도 높음. 하지만 모든 쿼리-문서 쌍을 개별적으로 모델에 입력해야 해서 비용이 크고 느림 
Dense Retriever 장점:
의미적 이해: 동의어나 다양한 표현 효과적 처리
풍부한 쿼리 표현: 복잡하거나 긴 검색 쿼리 의미 포착
Dense Retriever 단점:
높은 연산 비용
제한된 투명성: 블랙박스처럼 작동. 특정 문서가 왜 검색되었는지 해석 어려움
데이터 및 모델 의존성: 학습 데이터의 품질이나 모델 변경에 크게 영향 받음

Dense Retriever - Bi-encoder는 두 문자을 따로 인코딩. 빠르고 대규모 검색에 적합하나 정확도 낮음
Dense Retriever - Cross-encoder는 두 문장을 함께 처리함. 매우 느리지만 세밀한 상호작용을 포착하기 때문에 정확도 높음 

### Retrieval-augmented LM
추론 시 외부데이터 저장소를 불러와 활용하는 언어 모델
언어 모델에 검색 엔진 결과를 함께 이용 
언어 모델로부터 세계 지식 정보를 분리 
LM의 단점
1. 거대 언어 모델은 모든 지식을 자신의 파라미터에 다 저장하지 못함
2. 거대언어모델은 갱신이 어려움. 뒤쳐짐
3. 거대언어모델은 답변 해석과 검증 어려움
4. 기업 내부 정보는 학습에 사용 안됨

LM의 챌린지
1. 컨텍스트 길이를 늘려야 함
2. 검색 엔진 성능에 의존 검색 노이즈에 취약. 할루시네이션 발생
3. LLM의 사전 지식과 컨텍스트 간 충돌 발생 가능
 -> 솔루션: 컨텍스트 위에서 grounding 학습 강화하기(컨텍스트에서 근거 위주로 답변하라고 설정하기 등). 답변 회피/거절 학습
4. 복잡한 추론이 필요함. 문서에 오류가 있으면 오류를 대답

Noise Robustness: 외부 문서에 노이즈가 포함되어 있어도 올바른 답을 찾아내는 능력


## LLMs with Tool Usage(LLM Agent, Tool Use, MCP)
### Basic concepts of LLM Agents
Agent: 센서로 환경을 인지하고 actuator로 환경에 대해 액션을 통해 영향을 미치는 것들
LLM Agent: LLM을 핵심 구조(backbone)로 삼아 환경을 이해하고 행동을 수행하는 에이전트. 서치 에이전트, 심리상담 에이전트, 코드 에이전트 
LLM-first view: 기존 LLM을 활용한 시스템을 에이전트로 만듦
Agent-fist view: LLM을 AI 에이전트에 통합하여 언어를 활용한 추론과 의사소통을 가능하게 함. 로봇, 임바디드 에이전트 등 

에이전트가 갖추어야 할 요건들
도구 사용, 추론과 계획, 환경 표현, 환경 이해, 상호작용/의사소통
Tool set -> Environment -> perceiver -> controller -> 다시 처음으로 반복 

### Tool Usage in LLMs
Tool: 언어 모델 외부에서 실행되는 프로그램에 연결되는 함수 인터페이스. 함수 호출과 입력 인자를 생성함으로써 이 도구를 활용할 수 있다. 

도구 사용 패러다임
도구 사용: 두 모드 간 전환. 텍스트 생성 모드와 도구 실행 모드
도구 사용 유도법: 추론 시 프롬프트, 학습
툴 러닝(tool learning) 방식
모방 학습: 인간의 도구 사용 행동 데이터를 기록함으로써 언어모델이 인간의 행동을 모방하도록 학습 
멀티 모달 툴 러닝: 멀티모달 대규모 언어모델을 기반으로 도구를 정의하고 활용 


### Model context protocol(MCP)
외사/모델마다 각기 다른 툴 호출 방식 및 스키마를 개발. 호환성 부족하고 재사용 어려움
MCP: 언어 모델이 외부 툴과 상호작용하기 위한 표준화된 방식으로 정의한 프로토콜. 툴 호출, 응답 전달, 컨텍스트 공유를 하나의 공통 규격으로 처리 

MCP 아키텍처
MCP host: 하나 또는 여러 개의 MCP 클라이언트를 조정하고 관리하는 AI 애플리케이션
MCP Client: MCP 서버와의 연결을 유지하며 MCP 호스트가 사용할 수 있도록 MCP 서버로부터 컨택스트를 가져오는 구성요소
MCP Server: MCP 클라이언트에게 컨텍스트를 제공하는 프로그램 

MCP 계층(layer)
MCP는 두 계층으로 구성됨
데이터 계층: 클라이언트-서버 통신을 위한 JSON-RPC 기반 프로토콜. 라이프 사이클 관리, 툴, 리소스, 프롬프트와 같은 핵심 요소들이 포함
전속 계층: 클라이언트 서버 간 데이터 교환을 가능하게 하는 통신 메커니증과 채널
데이터 계층은 내부 계층. 전송 계층은 외부 계층

MCP 장점
표준화(동일한 호출 규격), 확장성(새로운 툴 추가 가능), 호환성(모델/플랫폼 상관 없이 같은 툴 호출 가능), 재사용성(한 번 정의한 툴을 여러 모델에서 활용 가능), 투명성(호출 과정이 기록/검증)

## AI Agents & Langchian
### Environment Representation & Understanding
에이전트가 환경을 이해하기 위해 필요한 것: 환경에 접근하기 위한 툴, 환경 표현, 환경을 이해/탐색하기 위한 방법론들 
환경의 표현: 텍스트(물리 세계 정보를 언어모델이 텍스트 기반으로 이해), 이미지(시각적 환경을 텍스트와 연결하여 지시 수행 및 환경 이해), 텍스트 기반 웹(웹 환경을 HTML, DOM, Accessibility Tree)로 표현하여 에이전트가 상호 작용 가능 
이미지 기반 표현의 문제점: 에이전트로서 좋은 성능을 내려면 세부적인 이해가 중요함

실시간으로 환경과 상호작용을 통해 지식을 발견해야 함
환경 특화 프롬프트: 환경에 맞게 수동으로 프롬프트를 제작하여 에이전트가 지시를 따르도록 유도 
문제점: 일반화. 특정 환경에서는 잘 작동하지만 새로운 환경에서는 성능이 떨어짐 

비지도 프롬프트 유도: 성공적으로 수행된 워크플로우를 기억하고 이를 기반으로 새로운 프롬프트를 생성하여 에이전트에 제공. 환경에서 상호작용을 메모리에 통합. 프롬프트를 사람이 수동으로 설계하지 않고 에이전트가 경험을 통해 자동생성 및 일반화

환경 탐색: 모델이 환경을 탐색할 때 보상을 부여하여 학습을 유도->호기심 기반 보상. 
탐색 기반 궤적 기억: 명령어를 샘플링 하여 실행한 뒤 더 정확한 새로운 명령어로 궤적을 재라벨링. LM-에이전트가 환경을 탐색하고 LM-라벨러가 이를 바탕으로 지시를 다시 정제
기존 데이터에 의존하지 않고 탐색과 자기 교정을 통해 데이터 생성
에이전트의 일반화 성능과 환경 적응력을 향상 

### Reasoning & Planning
Controller: planning 종류
국소적 계획: 한 단계씩 계획을 세움. 매 스텝마다 사용할 하나의 툴 결정. 단순하고 직관적이나 장기 의존성 문제 발생
전역적 계획: 실행 가능한 전체 계획 경로를 한 번에 생성. 여러 개의 툴을 조합하여 시퀀스 형태로 결정. 효율적이나 복잡한 환경에서는 실패 가능 

ReACT: 추론과 액션을 결합하여 에이전트가 환경과 상호작용하도록 하는 방식. 두 과정을 결합해 상황 적응형 계획 가능. 
plan-and-solve prompting: 전체 계획을 세우고 그 계획에 따라 순차적으로 문제 해결. 단순한 step-by-step 방식보다 체계적이고 안정적인 추론 가능. 복잡한 문제 해결에서 오류 축적 감소 

오류 식별과 회복: 에이전트는 에러/실수에서 회복할 방법 필요. 수행한 궤적을 평가 후 잘못된 부분을 Reflection 단계에서 분석하여 재시도하는 방식 

계획 재검토: 에이전트가 실행 도중 계획을 재검토하고 수정. 초기 계획이 불완전하더라도 실행 과정에서 보완 간으. 장기 작업에서 안전성과 성공률 향상.

### Langchain
LLM 기반 앱을 빠르게 개발할 수 있는 오픈 소스 프레임워크
LLM을 다양한 데이터/툴과 연결하여 강력한 앱 개발 가능 
다양한 LLM provider(OpenAI, Anthropic, Google 등)과 통합하여 모델/회사별 API 차이를 공통 인터페이스로 관리 가능
프롬프트, 메모리, 툴 같은 컴포넌트들이 모듈화 되어 있어 재사용성과 확장성 확보

## 2. 멀티 에이전트 시스템

LLM 한계

2. 자기회귀적 성격: 천천히 생각하거나 신중한 추론을 못함
3. 스케일링 법칙: 모델 크기 증가에 따른 성능 향상 둔화 

다중 에이전트 시스템
집단 지성: 지능형 에이전트끼리 팀을 이루고 협력하고 지식을 나누어 함께 문제를 해결 - 수평적 확장
예) 서포트 에이전트, 반대 에이전트, 리서치 에이전트1
LLM 기반 다중 에이전트 시스템 협업 요소와 메커니즘: 협업 유형, 전략, 소통 및 조직 구조

에이전트 구성 요소
에이전트: 역할, 능력, 행동, 지식 모델을 가진 핵심 행위자들
환경: 에이전트가 존재하고 인식 및 행동할 수 있는 외부 세계
상호작용: 표준화된 프로토콜을 사용한 에이전트 간 소통
조직: 에이전트들은 계층 구조로 관리되거나 자발적인 행동으로 조직

### 방법론
협업 유형
1. 협업, 역할 분담, 문서 품질 향상
2. 경쟁, 대립, 논증
3. 협력+경쟁, 균형 잡힌 판단

협업
에이전트들은 각자의 개별 목표를 공동의 집단 목표와 일치시켜 상호 이익이 되는 결과를 달성하기 위해 협력. 각자 특정 세부 작업에 집중
단점: 개별 에이전트의 성능에 크게 좌우, 에이전트 하나의 오류가 시스템 전체에 부정적 영향을 미칠 수 있음. 빈번한 통신과 다중 협업 채널은 계산 비용과 복잡성 증가 초래 

경쟁
에이전트들은 각자의 개별 목표를 우선시, 다른 에이전트의 목표와 충돌하거나 대립할 수 있는 경쟁 요소 도입. 에이전트들이 고도의 추론 능력과 더 창의적인 문제 해결 방법을 개발하도록 촉진
단점: 경쟁적 협업 경로는 강력한 프롬프트를 가진 단일 에이전트에 의해 따라잡힐 수 있음. 끝나지 않는 논쟁 가능 

협력과 경쟁 조합: 공동 목표에서는 특정 작업 협력, 다른 작업에서는 경쟁.
전문가 혼합 모델: 다양한 전문가 모델들이 최종 결과물에 기여하려고 경쟁하고 게이트 시스템이 각 입력에 맞는 최적의 전문가를 골라냄. 각자의 데이터의 서로 다른 측면에 대해 전문화하도록 훈련 

### 협업 전략
규칙 기반 프로토콜: 사전에 정의된 규칙. 시스템 동작과 특정 규칙을 쉽게 연결 가능해서 구현과 디버깅 용이. 합의 도출과 경로 찾기같은 절차가 명확하고 변동성이 적은 작업에 효율적

역할 기반 프로토콜: 사전에 정의된 역할. 주로 도메인 지식에 기반. 개별 모듈 재활용 가능성. 각 에이전트에 특정 책임을 할당. 

### 커뮤니케이션 구조
중앙집중형 구조: 참여자-서비스 제공자 구조.
서비스 에이전트: 시스템 안에서 참여자들 사이의 소통이나 협력을 관리, 제어, 조율하는 역할 담당
중앙 에이전트: LLM-블렌더는 한 라운드에서 서로 다른 LLM들을 호출하고 두 개씩 비교하여 순위를 책정한 후 최상위 응답들을 결합

탈중앙화 구조: 에이전트에 대한 통제 및 의사결정 분산
각 에이전트는 에이전트와의 제한적 통신과 일부의 정보를 바탕으로 작동. 상호작용과 의사결정을 위한 정교한 알고리즘이 필요
에이전트들이 분산형으로 서로 직접 소통하는 방식. 일부 에이전트가 실패해도 시스템이 계속 기능. 높은 확장성을 제공. 에이전트들이 자율적으로 작동

다중 에이전트 시스템 만들 때 필요한 것
확장성 고려사항
최적 협업 전략
적응가능한 역할 및 협업 경로 할당

## 3. Memory & Tool in Multi agent system
### 메모리 & tool
언어 모델에서 에이전트 시스템으로 패러다임 전환 
AI 에이전트는 실시간 정보에 접근하고 외부 도구를 활용하며 물리적 또는 디지털 세계와 상호작용하고 정적인 훈련 데이터를 넘어서서 적응 가능.
기억/지식-RAG, 메모리
행동/능동성-도구 호출
학습/적용-멀티 에이전트 학습 

검색 증강 생성 RAG: 신뢰할 수 있는 외부 소스에서 관련 정보 검색. 
일반 적 검색 증강 한계쩜: 정보를 한 번만 가져와서 품질 검토나 확인 과정 없음. 상태 정보를 저장하지 않아 여러 단계의 추론 못함. 맥락 유지 못함. 웹 검색같은 외부 툴과 API가 요구되는 경우 존재
-> 에이전트형 RAG로 해결 

에이전트형 RAG: AI 에이전트가 RAG 파이프라인을 향상시켜 각 단계들을 조율하고 단순한 검색/생성을 넘어서는 역할을 하도록 함
주요 구성 요소
-LLM
-메모리
-계획
-도구. 

훈련 방법
고려사항
언제: 매개 변수 기반 지식으로 답할지 도구를 호출할지 결정
무엇을: 적절한 도구 선택
어떻게: 선택한 도구의 API에 올바른 인수 전달
이런 의사결정 단계뜰이 모여 에이전트의 행동 정책(policy)형성. 강화학습을 통해 효과적으로 학습 

Toolformer: 언어모델이 스스로 도구 사용법 학습 . 인간 주석 없이 자신이 생성한 API 호출 예시로부터 학습
Gorilla: 대규모 API에 LLM을 연결. API 세트를 안정적으로 호출하고 사용할 수 있도록 정확도와 근거, 기능을 향상. 
ReTool: LLM의 전략적 도구 사용을 위한 강화학습. 외부 도구를 사용하는 시점, 도구 선택, 방법을 학습시켜 복잡하고 계산 집약적인 작업에서의 LLM 추론 능력을 향상. 
Search-R1: LLM을 사용한 더 나은 웹 검색을 위한 강화 학습. LLM 에이전트가 자율적으로 다단계 웹 검색을 수행하여 답변의 정확성과 관련도를 개선하도록 함

### 5. Domain-specific AI agent
Deep Reasearch의 배경
웹 검색 -> LLM 챗봇 -> RAG -> 에이전트 기반 심층 연구

에이전트 기반 심층 연구
LLM은 다단계 추론과 검색을 결합
동적 피드백 루프를 형성: 검색 결과에 대해 추론하고 이 추론은 이후 검색 과정을 조정
간단한 응답 생성기가 아니라, 능동적인 정보 탐색 에이전트 역할. 다른 도구나 에이전트와 협력 

역동적인 환경에서의 어려움
- 검색과 추론의 결합 어려움: 기존 RAG 파이프 라인은 검색한 다음 추론하는 고정된 순서를 사용해서 오류 축적 ->에이전트 기반 접근법은 추론이 언제 무엇을 검색할지 결정하도록 하여 오류 전파를 줄일 수 있음
- 적응력 한계: 프롬프트와 지도 학습에 대한 의존으로 새로운 환경에 대한 유연한 전략을 개발하기 어려움. 시행 착오를 통해 최적의 전략을 배우려면 강화 학습 필요
- 효율적인 리소스 할당: 검색과 추론 둘 다 토큰과 시간 소비. 작업 유형에 따라 검색/추론 리소스 비율을 동적으로 조절하는 기술 필요

강화학습 기반 훈련 및 보상 설계
프롬프트: 예시로 ReAct는 추론+행동 구조를 사용하여 프로세스를 검색 및 추론 단계로 분할
지도학습: Toolfomer는 훈련 데이터의 패턴을 기반으로 도구를 사용하는 법을 학습
강화학습: 모델이 독립적으로 최적의 검색 및 추론 전략을 발견하도록 유도. R1-Searcher와 DeepResearcher 등이 있음

Test-Time Scaling(TTS)
정의: 추론/검색 단계 수를 늘리면 성능 향상으로 이어진다
추론 TTS: 추가적인 추론 단계(CoT, Self-Refinement, Self-Consistency)를 도입해서 정확도를 향상
검색 TTS: 반복적, 다단계 검색으로 정보 수집 범위 확장
trade-ff: 검색과 추론 둘 다 자원을 소모하므로 최적 비율 조정 

방법론-문제 해결 과정
생각 -> 도구 사용 -> 생각 -> 답변 사이클 반복
생각 단계에서 세부 목표를 세우고 검색할 내용을 결정
검색 에이전트가 검색 API를 사용해서 상위 k개 결과를 가져옴 
탐색 에이전트가 웹페이지 내용을 읽고 유용한 정보를 단기 저장소에 모아둠
읽는 과정에서 에이전트는 계쏙 읽을 건지 그만둘 건지, 어떤 내용을 저장할 건지 판단
