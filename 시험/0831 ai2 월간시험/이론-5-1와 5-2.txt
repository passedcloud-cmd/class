# 5-1 파인튜닝 및 AI모델 활용-리소스 효율적 AI모델
## 1. 컴퓨터의 수 체계
### 고정소수점 수 체계 
Most Significant Bit(MSB): 이진수에서 가장 왼쪽에 있는 비트. 가장 큰 자리값.
Least Significant Bit(LSB): 이진수에서 가장 오른쪽에 있는 비트. 가장 작은 자리값
Nibble: 4비트로 이루어진 데이터 단위

부호-크기 표현 방식: 최상위 비트MSB를 부호 비트로 사용하여 0이면 양수, 1이면 음수를 나타내고 나머지는 비트 절댓값을 표현하는 방식
0을 표현하는 방식은 2가지가 있음. 1000과 0000 

2의 보수 표현 방식: 음수를 표현할 때 해당 수의 절댓값을 이진수로 쓰고 모든 비트를 반전한 뒤 1을 더하는 방식

N-bit 수를 M-bit 수로 확장(M>N)
부호 확장: 최상위 비트를 복사해 상위 비트를 채움(값을 일정하게 유지)
제로 확장: 상위 비트를 모두 0으로 채움(패턴을 일정하게 유지)

N-bit 패턴이 꼭 정수일 필요는 없음
정수부와 소수부를 N-bit 패턴에서 함께 표현할 수 있음
K-bit 정수부, M-bit 소수부
정수부와 소수부 사이에 이진 소수점
이진 소수점 위치는 실제로 저장하지 않음. 사용자가 직접 저장함. 
곱셈과 나눗셈은 scaling factor 체크

고정소수점 간단 설명
소수점의 위치가 항상 고정되어 있는 방식이에요.
예를 들어 "항상 정수 부분 4자리, 소수 부분 2자리"로 정하면:
1234.56
0012.34
9999.99
장점: 계산이 단순하고 빠름
단점: 표현할 수 있는 범위가 좁음 (아주 크거나 아주 작은 숫자는 못 담음)

### 부동소수점 수 체계
고정소수점을 표현할 경우에 너무 많은 비트를 표현함
지수를 활용하여 수를 표기 
정해진 자리 수만 사용
언제나 x.xxx * 10^x 형태로만 표현하기로 함 -> 정규화
유효숫자 다음은 반올림, 올림, 버림, 절삭 등 

부호, 지수, 부호 없는 가수 

부동소수점 간단 설명
소수점이 필요에 따라 움직이는(떠다니는, float) 방식이에요. 과학 표기법을 떠올리면 쉬워요.
123.456 = 1.23456 × 10²
0.000123 = 1.23 × 10⁻⁴
큰 숫자든 작은 숫자든, "숫자 부분"과 "소수점을 몇 칸 옮길지(지수)"를 따로 저장해서 소수점 위치를 유동적으로 표현해요.
장점: 아주 큰 수부터 아주 작은 수까지 넓은 범위 표현 가능
단점: 계산이 복잡하고, 미세한 오차(반올림 오차)가 생길 수 있음

## 모델 경량화의 필요성
AI/ML의 문제: 모델 크기, 컴퓨팅 리소스, 학습 비용
### 양자화(Quantization)
연산/메모리 부하를 줄이는 가장 직관적인 방법
clipping range에 따른 scaling factor를 정하는 것이 첫 단계

QAT(Quantization-aware training)
학습 단계에서(forward pass) 양자화를 함께 수행. 학습 데이터 필요
동일 accuracy 기준 압축률을 높일 수 있으나 학습 복잡도가 엄청 상승(retrain/fine-tuning 접근)
모델 사이즈를 크게 만들고 양자화한 모델이 모델 사이즈 작은 것과 accuracy 비슷하거나 좋음

PTQ(Post-training quantizaion)
LLM처럼 모델도 학습데이터도 너무 큰 경우엔 QAT 사용 불가
사전학습된 모델을 바탕으로 양자화 수행

weight-activation vs weight-only
모델 사이즈에 얼마나 집중할 것인가?(정확도 손실을 어디까지 허용할 것인가?)
De-quantization 과정을 얼마나 허락할 것인가?


Weight (가중치): AI 모델이 학습한 "지식"이 저장된 숫자들. 학습이 끝나면 값이 고정됨.
Activation (활성화값): 모델이 실제로 계산할 때(입력을 넣었을 때) 중간중간 생기는 숫자들. 입력이 바뀔 때마다 값도 바뀜.
양자화란 이 숫자들을 원래 32비트짜리 정밀한 실수(float32) 대신, 더 적은 비트(8비트, 4비트 등)로 뭉뚱그려 저장해서 모델을 가볍고 빠르게 만드는 기법이에요.

Weight-Only 양자화
가중치만 압축하고, 활성화값은 그대로(보통 16비트) 둬요.
모델 파일 크기를 줄이는 게 주 목적
계산할 때는 압축된 가중치를 다시 풀어서(복원) 계산
상대적으로 정확도 손실이 적음
비유하면: 책(가중치)은 압축 파일로 저장해두고, 읽을 때(계산할 때)는 펼쳐서 읽는 것과 비슷해요.

Weight-Activation 양자화
가중치와 활성화값 둘 다 압축해요.
계산 자체를 저비트 숫자로 직접 수행 → 속도가 더 빠름
하드웨어(예: 저비트 연산에 최적화된 칩)를 제대로 활용 가능
다만 활성화값까지 뭉개기 때문에 정확도 손실 위험이 좀 더 큼

W8/A8 Quant. = Weight를 8비트로, Activation을 8비트로 압축한다는 뜻이에요.
W4/A16 Quant. = Weight는 4비트로 압축, Activation은 16비트(원래에 가까운 정밀도) 유지

FP16, FP8, INT8, INT4란?
숫자 하나를 몇 비트(bit)로, 어떤 방식으로 저장할지를 나타내는 "숫자 표현 형식"

FP = Floating Point (부동소수점)
부동소수점 방식으로 숫자를 저장해요. 소수점이 움직이며 넓은 범위의 숫자(아주 크거나 작은 값)를 표현할 수 있어요.

FP16 (16비트 부동소수점)
원래 많이 쓰이는 FP32(32비트)의 절반 크기
정밀도는 좀 떨어지지만 범위는 꽤 넓게 표현 가능

FP8 (8비트 부동소수점)
비트가 적으니 저장 공간도 적게 쓰고 계산도 빠름
대신 표현할 수 있는 정밀도와 범위가 더 좁아짐

INT = Integer (정수)
정수로만 숫자를 표현하는 방식이에요. 소수점 개념 자체가 없고, 대신 "이 정수가 실제로는 어떤 실수를 의미하는지"를 별도의 배율(scale) 값과 함께 계산
예: 실제 값 0.75를 저장할 때, INT8로는 정수 96 + "이 값에 1/128을 곱하면 실제 값"이라는 스케일 정보를 같이 저장하는 식이에요.

INT8 (8비트 정수)
보통 -128 ~ 127 사이의 정수만 표현
양자화에서 가장 널리 쓰이는 표준 포맷 (앞서 말씀드린 W8/A8이 이것)
정수 연산이라 계산이 매우 빠름

INT4 (4비트 정수)
보통 -8 ~ 7처럼 아주 좁은 범위의 정수만 표현
극도로 압축된 형태 (W4/A16의 그 "4"가 이것)
모델 크기를 크게 줄일 수 있지만, 표현 가능한 값의 개수가 적어서(4비트면 16가지 값뿐) 정확도 손실 위험이 큼

정리
비트 수가 작을수록 → 모델은 가벼워지고 빨라지지만, 정확도는 떨어질 위험이 커져요.
FP(부동소수점)는 넓은 범위를 유연하게 표현하고, INT(정수)는 계산이 단순하고 빨라요.
그래서 "W4/A16"이라고 하면 가중치는 INT4로 확 줄이고, 활성화값은 FP16으로 정밀하게 유지하는 조합인 거예요.


### 가지치기(pruning)
불필요한(기여도가 적은) weight를 제거
저장해야 하는 weight가 적어지면서 모델 크기가 줄어들게 됨
살아남은 weight의 위치를 기록하기 위한 추가 정보 필요(indexing data 등)
양자화되지 않은 상황에서도 가지치기가 가능한 경우가 많음
다만 GPU 상에서 속도 이득을 보기에 어려운 경우가 많음(전용 가속기 설계 필요) 

Pruning rule
가지치기 대상의 순서를 어떻게 정할 것인가
magnitude-based pruning
pruning ratio 압축률 대비 높은 accuracy를 유지하는 다양한 기법 존재 

unstructured vs structured(unstructed일수록 가지치기 비율 높음)
추론 효율과 accuracy 방어 사이의 선택
channel/layer 수준의 극단적인 structured pruning 활용 가능
indexing data format

Rine-tuning/retraining 가능 여부
양자화의 경우와 비슷
작은 모델에서는 학습 단계부터 도입 가능(CNN 등)
LLM처럼 큰 경우에는 post-training 가지치기가 현실적
CNN기반 이미지 처리는 80% 이상 가지치기 가능(accuracy drop 1~2%)
언어 처리 LLM 계열은 50% 내외

GPU호환 여부
GPU가 감당할 수 없는 가지치기 패턴이 형성되는 경우 있음

### 지식 증류
똑똑하지만 매우 큰 모델 = 선생님
동일한 문제를 푸는 작은 모델 =학생 
Total loss = Student loss + Distillation loss
student loss : ground truth의 student 추론 차이
Distillation loss: 동일 데이터에 대해 teacher와 student의 결과 차이 

조교(assistant model) 활용하기
학생의 잠재력이 고정이고 선생이 너무 똑똑하면 효율 떨어짐
선생님이 고정이면 학생의 잠재력이 너무 뛰어나도 효율 떨어짐
조교가 가운데에서 간극을 메워줌 

조교의 효과
학생을 바로 학습(No Knowldeg Distillation)
선생님 혼자 학생 교육(Baseline Knowlege Distillation)
조교의 개입(Teacher Assistant Knowledge Distillation)

LLM distillation
상대적으로 작은 LLM 학습에서 기존 LLM 활용
데이터가 너무 크면?
합성 데이터 활용: 프롬프트 데이터로 선생님 모델의 응답을 뽑고 학생을 fine tuning. 

### 파인 튜닝
원본 모델의 크기를 줄이는 과정이기도 함
일부/전체 학습 데이터를 바탕으로 떨어진 accuracy를 복원하기 위한 과정
혹은 비슷한 개념을 학습 초기부터 수행

튜닝 방법론
In-context학습: 원본 모델을 두고 원하는 방향으로 동작을 튜닝하기 위한 프롬프트 고민

Full fine tuning: 특정 도메인의 데이터를 사용하여 원본 모델의 모든 weight를 fine tuning
장점) 처음부터 새로 학습하는 것에 비하여 적은 데이터만 활용해도 도메인에 특화 가능
장점) 도메인 특화 관점에서 accuracy 이득 기대 가능
단점) 원본 모델이 일반적으로 크기에 모든 weight를 갱신하는 학습 비용 부담
단점) 사실상 처음부터 학습하는 수준일 수도
단점) 원본 모델의 weight 자체가 변하는 과정에서 기존 학습 정보의 망각이 일어날 수 있음 

PEFT 파라미터 효율적인 파인 튜닝(Parameter Efficeint Fine Tuning)
복잡도 개선

Adapter layer: 보통 MLP 형태. 입력원본 모델 내부에 새로운 레이어 추가. 목표로 하는 특화 데이터를 활용하여 adapter layer만 학습(원본 weight는 고정)
Full tuning보다는 적지만 상당히 많은 추가 weight 필요. 대신 꽤 높은 표현력 제공. 사실상 원본 모델의 구조가 바뀌고 adapter layer의 메모리/연산 오버헤드가 큼

prompt tuning: 입력 임베딩 앞/중간에 학습 가능한 가짜 토큰 추가. 원본 모델의 구조를 전혀 건드리지 않고 아주 적은 추가 weight로 입력을 조정하여 특정 동작을 유도. 매우 가볍고 배포가 쉽지만 표현력의 한계로 성능에 제한 있음

Low-Rank Adaptation(LoRA)
특정 weight matrix(base wight)에 low-rank updater를 추가
원본 weight를 고정하고 추가되는 low-rank weight만 학습
높은 표현력에 adapter layer보다 훨씬 적은 추가 weight

QLoRA(경량화된 Low-Rank adaptation)
경량화 + LoRA
원본 모델을 강하게 원자화(NF4 4bit normal format)
LoRA를 적용하는 low-rank weight는 BF16등 높은 해상도를 유지하면서 학습
전체 모델의 복잡도를 대폭 줄이면서 목표로 하는 task에 대해서는 적어도 높은 성능을 달성  


BF16과 NF4란?
BF16 (bfloat16, Brain Floating Point 16)
FP16과 같은 16비트 부동소수점이지만, 비트를 나누는 방식이 달라요. 여기서 잠깐 부동소수점의 구조를 짚어볼게요.
부동소수점 숫자는 크게 두 부분으로 이루어져 있어요:
지수부(exponent): 숫자의 "범위"를 결정 (얼마나 크거나 작을 수 있는지)
가수부(mantissa): 숫자의 "정밀도"를 결정 (얼마나 세밀하게 표현하는지)
FP16	지수부 5비트 + 가수부 10비트
BF16	지수부 8비트 + 가수부 7비트
BF16은 표현 범위는 FP32와 같지만 정밀도는 줄어서 세밀함은 뭉개짐
숫자가 너무 커지거나 작아져서 오버플로우 나는 걸 막기 좋아서, AI 학습에서 FP16보다 BF16을 선호하는 경우가 많아요.

NF4 (NormalFloat 4-bit)
4비트짜리 특수한 포맷인데, 앞서 말씀드린 일반 INT4와는 조금 달라요.
일반 INT4는 -8~7 같은 정수를 균등한 간격으로 배치해요. 그런데 실제 AI 모델의 가중치 값들을 보면, 값이 균등하게 퍼져있지 않고 0 근처에 몰려있는 정규분포(종 모양) 형태를 띠는 경우가 많아요.
NF4는 이 점을 이용해서:
값이 자주 나오는 구간(0 근처)에는 눈금을 촘촘하게
값이 드물게 나오는 구간(양 극단)에는 눈금을 듬성듬성
배치해서, 같은 4비트라도 실제 가중치 분포에 더 잘 맞도록 설계된 포맷이에요.
같은 4비트를 쓰면서도 일반 INT4보다 정확도 손실이 적음. QLoRA 같은 경량 파인튜닝 기법에서 많이 쓰여요.

# 5-2 AI 모델 활용 - On-device AI 플랫폼 및 100% 정수연산 양자화
## 1. 온디바이스 AI 하드웨어 및 플랫폼
### 온디바이스 AI 하드웨어

### 2. 100% 정수연산 양자화의 필요성
AI 가속기의 구동 특성
정수 연산만 지원하거나 정수 연산에서 훨씬 효율적으로 동작 

일반적 양자화: r이라는 실수를 q라는 정수로 표현하고 싶다
-> 무한한 실수를 모두 나타내는 것은 불가능하니 유한한 관심 범위를 지정
8비트 정수 [0, 255]로 [rmin, rmax]범위의 실수를 표현하려면 2가지 파라미터가 필요함
스케일링 파라미터 S(실수), 오프셋 파라미터 Z(정수)
r= S(q-Z)
문제는 스케일링 파라미터가 실수라는 것. 양자화 후 정수 q만 사용해서 연산할 것 같았지만 실제로는 실수 값 r에 매핑하기 위해 숨어있는 스케일링 파라미터 S가 개입하여 실수 연산이 필요함 -> AI 가속기 구동 불가

### 3. 정수연산 양자화
실수 행렬의 연산 과정을 양자화 관점에서 유도
스케일링 파라미터를 정수화 하여 정수 연산으로 유도
스케일링 파라미터를 변수 한 개 M으로 묶음

스케일링 파라미터(실수)를 뭉쳐서 M으로 나타냈으므로 M을 별도로 미리 양자화시키면 실수 연산이 사라짐
문제점: M이 실제로는 (0,1)사이의 값이므로 정수로 나타내기 어려움
해결책: 비트 쉬프팅

비트 쉬프팅 과정: 임시로 스케일 업(정수화) -> 양자화 및 연산 -> 스케일 다운. 그러면 실수가 사라져서 정수 연산 됨

#### 배치 정규화(Batch Normalization)
학습 중 정규화를 통해 입력 분포의 변화를 줄여 안정적인 학습을 돕는 기법
BN 계층에서도 실수 연산이 필요
그러나 BN계층에서 별도로 양자화를 진행하면 비효율적
그래서 폴딩 기법 사용

BN 폴딩: BN 연산을 바로 앞의 Conv 계층 연산에 통합해서 함께 양자화

SoftMax
GELU

## AI 모델 활용 - 테스트 타임 도메인 적응
### 1. 분포 이동과 테스트 타임 도메인 적응 TTA
분포 이동: 학습 데이터에서 경험하지 못했던 낯선 데이터에 맞닥뜨리는 현상. AI 성능 하락의 주요 원인 

테스트타임 도메인 적응(Test-Time Adaption TTA)
테스트 데이터의 분포를 파악하여 모델을 유연하게 적응시킴
테스트 데이터를 입력받을 때 모델의 일부를 새 데이터의 통계에 맞게 재조정하여 성능을 유지

### 2. TTA 기법
#### CNN 기반 TTA 기법
TENT: 배치 정규화 계층을 테스트 데이터에 최적화
평균 분산 업데이트: 테스트 데이터를 입력하면서 batchNorm의 평균과 분산을 테스트 데이터 기준으로 재계싼. 모델이 새로운 데이터 분포에 즉각 적응
어파인 파라미터 업데이트: 테스트 데이터의 엔트로피를 손실 함수로 설정. 역전파를 통해 스케일과 이동 값을 미세 조정. 예측의 확신도를 높이는 방향으로 적응
학습 재진행 없이 테스트 데이터 분포에 맞게 모델 즉시 최적화

SAR: 최적화를 더욱 안정적으로
관찰: 일부 테스트 데이터가 노이즈가 많거나 이상치면 큰 gradient를 만들어 모델이 불안정
테스트 샘플 선택: 엔트로피(불확실성)가 낮은 테스트 샘플만 선택해 모델 업데이트에 반영
안정적 엔트로피 최소화: 엔트로피 손실이 너무 요동치지 않도록 평탄화
결과: TENT보다 학습이 안정적이고 테스트 환경에서도 성능 유지

#### 비전언어모델 기반 TTA 기법
TPT(Test-Time Prompt Tuning): 일관성 있는 예측을 돕자
테스트 이미지마다 여러 증강을 생성
엔트로피가 가장 낮은 이미지를 6개 선택
6개의 평균 엔트로피를 로스로 세팅하고 이를 최소화하도록 텍스트 프롬프트 업데이트

promptAlign: 학습 데이터와 테스트 데이터를 직접 정렬 시키자.
학습 데이터 통계까지 활용해 분포 정렬을 수행
학습 데이터와 테스트 데이터의 통계적 차이를 최소화하도록 설계
두 데이터의 인코딩 결과를 계층별로 정렬
학습 시 얻은 feature 분포와 테스트 feature 분포를 정렬
추가적으로 엔트로피 로스를 함께 사용하여 안정적인 예측 유지
최종적으로 텍스트 프롬프트 + 이미지 프롬프트 모두 업데이트 


## AI 활용 - 적응적 센싱
### 초거대 AI
분포 이동의 문제
스케일링 법칙: 모델 크기, 학습 데이터 양, 컴퓨팅 자원이 증가함에 따라 AI 모델 성능 향상. 예측 가능한 투자 전략

보완책으로 적응적 센싱이 필요 

### 적응적 센싱으로 분포 이동 억제
적응적 센싱: 환경에 맞춰서 센서를 조절해서 좋은 데이터만 받자
분호 이동 억제
ID: 학습 데이터 영역 (선명한 말 사진)
C-OOD: 학습 데이터와 의미는 같지만 외형이 다름(흐릿한 말 사진)
PDD: 완전히 본 적 없는 데이터 (강아지)
모델 일반화: 모델 지식 영역을 확장하여 분포 이동 억지
적응적 센서 방식:센서 제어를 통해 다양한 데이터를 모델이 아는 영역(ID) 안으로 넣어줘서 분포 이동 억제 

### 적응적 센싱을 위한 데이터셋

SenseShift6D(물체 6D 포즈 추정 태스크)
