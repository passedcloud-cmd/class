평가: 표현식을 계산하여 그 결과인 '값'을 만들어 내는 과정
값: 표현식이 평가된 결과.
	예) 10.1, True, "안녕"

변수: 값을 재활용하기 위해 붙이는 고유 이름
값에 할당함.
메모리 주소
degrees = 35
35 값이 저장된 메모리를 가리키는 이름표의 이름이 degrees
객체: 값, 타입, 메모리 주소, 행동(함수)를 묶은 개념
재할당: 변수가 가리키는 대상을 변경

타입: 데이터 종류. 값(피연산자)과 값에 적용할 수 있는 연산자 2가지 요소로 구분
데이터 타입 5가지
Numberic Types : int, float, complex(복소수)
Text Sequence Type: str
Sequence Types: list, tupble, range
Non-sequence Types: set, dict
기타: Boolean, None, Functions

지수표현법: 1.23 * 10^9 = 1.23e9
산술 연산자

Sequence Typles
값을 순서대로 나열. indexing[1], slicing[1:4], length, Iteration(반복. for i in my_data) 가능
str, list, tuple, range
str: 변경 불가능. 시퀀스.
my_str = 'hello'이 있는데 my_str = 'ha'로 작성하면
my_str을 변경한 게 아니라 새 값으로 재할당 한 것.
f-string

할당문(x = 100), 정의문(def my_function()), 제어문(pass, break, continue), 조건문(if), 반복문(for, while)
표현식과 달리 하나의 값이 나오지 않음.
예) x =10는 x라는 변수에 10을 할당했을 뿐 값이 나오지 않음.

Style Guide: 규칙과 권장 사항

## 파이썬 syntax 2
리스트: 여러 값을 순서대로 저장(시퀀스), 변경 가능 자료형, 모든 데이터 종류를 담을 수 있음
[ ]로 표현
중첩 리스트: 다른 리스트를 값으로 가진 리스트

튜플: 여러 값을 순서대로 저장(시퀀스), 변경 불가능 자료형, 모든 데이터 종류를 담을 수 있음
( )로 표현. 소괄호 생략 가능
my_empty_tuple = ()
my_tuple = 1, 3, 5
단일 요소 튜플 my_tuple = (1, )
튜플은 데이터의 안정성과 무결성 보장
다중 할당, 값 교환, 함수 다중 반환 값 등등 가능

range: 연속된 정수 시퀀스(순서)를 생성, 변경 불가능 자료형
range(start, stop, step)
list로 형변환 가능
print(list(range(5))) # [0, 1, 2, 3, 4]
start와 stop이 맞지 않으면 list 형변환 시 빈 리스트 [] 나옴

dictionary: key-value 쌍으로 이루어짐. 변경 가능. 순서 없음. 중복 없음.
key는 중복 안됨. 변경 불가능한 자료형만 사용 가능.

set: 순서 없음. 중복 없음. 변경 가능
중괄호 사용
my_empty_set = set()
집합 연산 가능
print(set1 | set2) 합집함
print(set1 - set2) 차집함
print(set1 & set2) 교집합

Other types
None : 값 없음. 정해지지 않음.
Boolean: True / False
예시) print(10 > 5) # True

Collection
여러 개의 값을 하나로 묶어 관리
str, list, tuple, range, set, dict

불변과 가변
형변환: 다른 데이터 타입으로 변환
암시적 형변환(자동): Boolen과 Numeric type들간의 계산
명시적 형변환(개발자가 지시): 함수로 지정
	변환할 수 없으면 ValueError 나옴

연산자
산술 연산자(+ - / * ** // %)
복합 연산자(+= -= /= *= ) 
비교 연산자(< <= > >= == != is is not)
==연산자는 동등성. 값이 같은지
is 연산자는 식별성. 같은 메모리 주소를 가리키는지. 싱글턴 객체 비교할 때 사용

싱글턴 객체: 단 하나의 객체만 생성되어 재사용되는 특별 개체
여러 변수가 이 값을 가지더라도, 모두 미리 만들어진 하나의 객체를 함께 가리킴. 항상 같은 메모리 주소
None, True, False

논리 연산자(and or not)
단축 평가: 두 번째 피연산자를 평가하지 않고 결과 결정
result = item1 and item2
둘 다 True면 result에 item2만 저장됨
item1이 False면 result는 빈 값이 됨

멤버쉽 연산자(in not in)

시퀀스형 연산자(결합 연산자 +, 반복 연산자 *): 시퀀스 자료형에서 사용

Trailing Comma 후행쉼표: 컬렉션의 마지막 요소에 붙음. 단일 튜플 말고는 선택사항
마지막 요소 뒤에 후행 쉼표 추가.

# 9번
x = 0
print(x or 5) # 5가 출력됨
# 0은 False로 취급되기 때문에 다음으로 넘어감.
만약 print(x and 5)이면 0이 출력됨.

# 3장 파이썬 function
함수(function): 특정 작업을 수행하기 위한 재사용 가능한 코드 묶음

def(함수 정의) 아랫줄에 있는 게 전부 function body

함수 이름과 소괄호를 적어서 함수 호출 my_function(100)

매개변수: 함수를 정의할 때 함수가 받을 값을 나타내는 변수
인자: 함수 호출 시, 실제로 전달되는 값

인자 종류
1. 위치 인자: 인자의 위치에 따라 전달. 반드시 인자를 전달해야 함
2. 기본 인자 값: 매개변수에 기본값을 할당. 인자를 전달하지 않으면 기본값이 할당됨
3. 키워드 인자: 인자의 이름과 값을 함께 전달. 위치인자와 함께 쓸 거면 뒤에 인자를 둬야 함
print(name='alice')
4. 임의의 인자 목록
정해지지 않은 개수의 인자를 처리
함수 정의 시 매개변수 앞에 * 붙임
여러 개의 인자를 tuple로 처리
5. 임의의 키워드 인자 목록
정해지지 않은 개수의 키워드 인자를 처리
함수 정의 시 매개변수 앞에 **를 붙여 사용 
여러 개의 인자를 dictionary로 묶어 처리

보통 위치 - 기본 - 가변 - 가변 키워드 순으로 작성 권장
def my_func(pos1, pos2, default_arg='default', *args, **kwargs):

재귀 함수(recursion): 함수 내부에서 자기 자신을 호출하는 함수
base case(종료 조건)에 수렴
종료 조건이 명확하고 반복되는 호출이 종료 조건을 향해야 함
스택 오버플로우: 일이 너무 많이 쌓여 멈추는 오류

내장함수(bulit-in function)
import 안 해도 사용 가능

파이썬의 범위 scope
함수 내부에 local scope: 함수 내부에서만 참조 가능
그 외에 global scope: 코드 어디에서든 참조 가능 공간
global variable과 local variable
변수 수명 주기 : 변수가 선언되는 위치와 scope에 따라 결정
1. built-in-scope: 파이썬이 실행된 이후 영원히 유지. 정의하지 않고 사용할 수 있는 모든 것.
None, True, False같은 상수/값, 내장 함수, 내장 예외 클래스(TypeError, ValueError 등), 내장 클래스/타입(int, float, str, list 등)
2. global scope: 모듈이 호출된 시점(그 파일의 코드가 실제로 실행되기 시작한 시점) 이후 혹은 인터프리터가 끝날 때까지(파이썬 프로세스 자체가 종료되는 시점) 유지
3. local scope: 함수 호출이 생성되고 종료될때까지 유지

이름 검색 규칙(Name Resolution)
LEGB Rule
local → enclosed → global → built-in 순으로 이름을 찾음
안쪽에서 변수 찾으면 바깥쪽으로 이동 안함

global 키워드: 변수의 스코프를 전역 범위로 지정
함수 내부에서 global 키워드 선언 전엔 참조 불가, 매개변수에는 global 키워드 사용 불가

함수 스타일 가이드
단일책임 원칙: 모든 객체는 하나의 명확한 목적과 책임만 가지기

packing: 여러 개의 데이터를 하나의 컬렉션으로 담는 과정
unpakcing: 컬렉션에 담겨있는 데이터들을 개별 요소로 펼쳐놓는 과정
튜플이나 리스트 등의 객체의 요소들을 개별 변수에 할당
시퀀스 언패킹 또는 다중 할당이라고 부름

함수는 하나의 값만 반환. 여러 값도 하나의 튜플로 패킹해서 반환

람다 표현식: 익명 함수를 만드는 표현식. 한줄로 간단
lamdba 매개변수: 표현식

3. 검색, 삽입, 삭제를 빠르게 수행

해시: 임의의 크기를 가진 데이터를 고정된 크기의 고유한 값으로 변환
해시 함수(해시 알고리즘): 임의 길이 데이터를 입력 받아 고정 길이 정수(해시값)로 변환해주는 함수

set

→ 순서를 보장하지 않음

dict

순서 보장 안함

이로 인해 동일한 데이터라도 매번 해시 값이 달라져 버킷 배치가 변함

해시 테이블(set과 dict의 key)에는 hashable만 저장 가능
항상 같은 해시 값을 유지해야 하기 때문

# 7장 파이썬 객체 지향 프로그래밍 OOP1
절차 지향 프로그래밍(procedural programming):
함수와 로직 중심 작성.
데이터를 순차적으로 처리
변수와 함수를 별개로 다룸

객체지향 프로그래밍(object oriented programming):
설계도가 클래스
설계도를 바탕으로 조립한 자동차가 인스턴스
자동차마다 색이 다르듯이 인스턴스는 다른 속성을 가짐

사람이라는 객체 안에 name, age와 이와 관련된 행동(메서드) 포함
데이터와 해당 데이터를 처리하는 메서드를 하나의 단위(객체)로 묶어서 관리
객체 간 상호작용과 메시지 전달이 중요
객체 지향은 절차 지향을 기반으로 두고, 객체라는 개념을 도입해 상속, 코드 재사용성, 유지보수성 등의 이점을 가짐

객체(object): 실제 존재하는 사물을 추상화한 것. 속성과 동작
클래스(class): 객체를 만들기 위한 설계도. 데이터와 기능을 함께 묶는 방법
클래스로 여러 개의 객체를 만들 수 있음
가수 클래스로 아이유, BTS 객체를 만들 수 있음

객체 특징
속성: 객체의 상태/데이터
메서드: 객체의 행동/기능
고유성: 각 개체는 고유한 특성을 가짐

클래스: 데이터(속성)와 기능(메서드)을 하나의 묶음으로 정의하는 설계도
사용자 정의 객체를 만드는 수단. 속성과 메서드를 정의
class 키워드.
클래스 이름은 파스칼 케이스(Pascal Case. 첫 단어의 첫 글자를 대문자로 표기하는 명명 규칙)방식으로 작성

인스턴스: 클래스를 통해 생성된 객체

클래스를 정의한다:
공통된 특성과 기능을 가진 틀을 만드는 것 → 새로운 타입을 만든다
예) 변수 named의 타입은 str 클래스 → 문자열 타입의 변수는 str 클래스로 생성된 인스턴스
예) 내가 정의한 Singer 클래스로 만든 객체 IU의 타입은 Singer 클래스
문자열 타입(클래스)의 객체(인스턴스)
하나의 객체는 특정 클래스의 인스턴스

클래스 구성요소
생성자 메서드: __init__메서드
인스턴스 생성 시 자동 호출
인스턴스 변수의 초기화 담당
새로운 객체를 만들 때 필요한 초기값을 설정

인스턴스 변수(속성)
각 인스턴스별 고유한 속성 - 인스턴스마다 독립적인 값 유지
self.변수명 형태로 정의

클래스 변수(속성)
모든 인스턴스가 공유하는 속성
클래스 내부에서 직접 정의

클래스 변수와 동일한 이름으로 인스턴스 변수 생성 시, 인스턴스 변수 먼저 참조

메서드: 클래스 내부에 정의된 함수. 해당 객체가 어떻게 동작할지를 정의
1. 인스턴스 메서드
2. 클래스 메서드
3. 스태틱 메서드

인스턴스 메서드: 인스턴스의 상태를 조작하거나 동작을 수행
반드시 첫 번째 인자로 자기 자신self를 받음
self 동작 원리
'hello'.upper()를 실행하면
str.upper('hello')로 작동함
인스턴스 메서드의 첫 번째 인자가 반드시 자기 자신인 이유
객체 스스로 메서드를 호출하여 코드를 동작하는 객체 지향적인 표현인 것
생성자 메서드(constructor method): 인스턴스 변수들의 초기 값 설정

클래스 메서드: 클래스 변수를 조작하거나 클래스 레벨의 동작을 수행
@classmethod 데코레이터를 사용하여 정의
호출 시 첫 번째 인자로 cls(클래스) 전달
클래스를 인자로 받아 클래스 속성을 변경하거나 읽음

스태틱(정적)메서드(static method): 클래스, 인스턴스와 상관없이 독립적으로 동작하는 메서드
@staticmethod 데코레이터를 사용하여 정의
호출 시 자동으로 전달 받는 인자가 없음(self, cls 안 받음)

# 8장 파이썬 객체 지향 프로그래밍 OOP1
상속(Inheritance)
한 클래스(부모)의 속성과 메서드를 다른 클래스(자식)가 물려받는 것
코드 재사용 가능. 계층 구조를 형성해서 더 구체적인 클래스를 만들 수 있음
기존 클래스의 수정이 필요하면 해당 클래스만 수정하면 되므로 유지 보수가 용이함.

메서드 오버라이딩(method Overriding. 덮어씌운다는 뜻)
부모 클래스의 메서드를 같은 이름, 같은 파라미터 구조로 재정의
일부 동작을 맞춤형으로 바꿀 때 유용

+ 오버로딩: 같은 이름, 다른 파라미터를 가진 여러 메서드를 정의하는 것(파이썬은 미지원)
파이썬은 마지막으로 선언된 메서드만 인식함

다중 상속
둘 이상의 상위 클래스로부터 여러 행동이나 특징을 상속 받음
중복된 속성이나 메서드가 있으면 상속 순서에 의해 결정
다이아몬드 문제
MRO(method Resolution Order) 알고리즘으로 메서드를 탐색할 클래스의 순서를 미리 정의함
C3 Linearization(선형화) 알고리즘으로 다음과 같은 순서를 결정
1. 자식 클래스 우선
2. 왼쪽 부모 우선(리스트에 나열된 순서) 탐색
3. 중복 방문 방지: 공통 부모 클래스는 모든 자식 클래스의 탐색이 끝난 뒤 단 한 번만 탐색

print(ClassName.mro())으로 순서 확인 가능

super() : MRO에 따라 현재 클래스의 부모 클래스의 메서드나 속성에 접근할 수 있게 해주는 내장 함수
super()를 사용하면 직접 부모 클래스 이름을 적지 않아도 MRO에 따라 자동으로 올바른 메서드를 찾아 실행 가능
1. 단일 상속에서 super()
부모 클래스를 직접 명시하지 않고 super()를 사용하므로, 나중에 클래스 이름이 바뀌거나 상속 구조가 변경되어도 super()호출 부분을 그대로 사용할 수 있어 유지보수성이 향상됨.
2. 다중 상속에서 super()
MRO(메서드 해석 순서)에 따라 각 클래스의 메서드를 찾아감

버그: 소프트웨어에서 발생하는 오류 또는 결함. 예상한 것과 다르게 작동하는 것.
디버깅: 프로그램의 오작동 원인을 식별하여 수정하는 작업
디버깅 방법 4가지
print 함수 활용, 개발환경(IDE) 등에서 제공하는 기능 활용, Python tutor 활용, 뇌 컴파일과 눈 디버깅

에러: 프로그램 실행 중에 발생하는 예외 상황. 문법 에러와 예외가 있음
문법 에러(syntax Error): 프로그램의 구문이 올바르지 않은 경우 발생. 오타, 괄호 및 콜론 누락 등.
코드 실행 이전에 발생함.

예외(Exception): 프로그램 실행 중에 감지되는 에러
내장 예외(built-in Exceptions): 예외 상황을 나타내는 예외 클래스
ZeroDivisionError: 0으로 나누기 
FileNotFoundError: 없는 파일 열기
NameError: 지역 이름 또는 전역 이름을 찾을 수 없음.
TypeError: 타입 불일치, 인자 누락, 인자 초과, 인자 타입 불일치
ValueError: 부적절한 값을 가진 인자를 받았고, 상황이 IndexError처럼 구체적인 걸로 설명되지 않으면 발생
IndexError: 시퀀스 인덱스가 범위를 벗어남
KeyError: 딕셔너리에 해당 키가 존재하지 않음
ModuleNotFoundError: 모듈을 못 찾을 때
ImportError: import하려는 이름을 찾을 수 없을 때
KeyboradInterrup: 사용자가 ctrl+c 또는 delete를 누를 때 발생. 무한루프 시 강제 종료
IndentationError: 잘못된 들여쓰기

예외 처리(Exception Handling): 예외가 발생했을 때 적절하게 처리하도록 하는 방법
try: 예외가 발생할 수 있는 코드 작성
except: 에외 발생 시 실행할 코드 작성
else: 예외가 발생하지 않았을 때 실행할 코드 작성
finally: 예외 발생 여부와 상관 없이 항상 실행할 코드 작성

except Exception:
범용적인 예외 처리. 모든 예외를 처리함. 맨 마지막에 두어야 함.

예외 객체: 예외가 발생했을 때 예외에 대한 정보를 담고 있는 객체
except 블록에서 예외 객체를 받아 상세한 예외 정보 활용 가능
as 키워드: print 구문과 함께 사용해서 error 변수에 담긴 예외 메시지를 출력하도록 할 수 있음

EAFP(Easier to Ask for Forgiveness than Permission): 예외처리를 중심으로 코드 작성.try-except
예외 상황을 예측하기 어려울 때 유용
LBYL(Look Before You Leap): 값 검사를 중심으로 코드를 작성. if-else
예외 상황을 미리 방지하고 싶을 때 유용
