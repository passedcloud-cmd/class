상속
한 클래스(부모)의 속성과 메서드를 다른 클래스(자식)가 물려받는 것
부모 클래스와 자식 클래스 간의 상하 관계가 형성
위쪽에 있는 부모 클래스가 본인의 속성과 메서드를 아래쪽 자식에게 넘겨줌

상속이 필요한 이유
1. 코드 재사용
반복되는 부분을 공통으로 두고 내려받음
2. 계층 구조
3. 유지 보수의 용이성
상속을 통해 기존 클래스의 수정이 필요한 경우, 해당 클래스만 수정하면 되므로 유지 보수가 용이함
코드의 일관성을 유지, 수정이 필요한 범위를 최소화

클래스 상속
상속 없이 구현하는 경우, 학생/교수 정보를 별도로 표현하기 어려움
교수/학생 클래스로 각각 선언하여 구현하면 메서드가 중복으로 정의됨


매서드 오버라이딩
부모 클래스의 메서드를 같은 이름, 같은 파라미터 구조로 재정의
부모 클래스의 메서드의 대신 자식 클래스의 메서드가 실행됨
부모 클래스의 기능을 유지하면서 동작을 자식 클래스에 맞춤형으로 바꿈
동일한 이름과 매개변수 사용해야 함

오버로딩(파이썬은 미지원)
같은 이름, 다른 파라미터를 가진 여러 메서드를 정의하는 것

파이썬은 하나의 메서드만 인식하며, 마지막으로 선언된 메서드만 인식함

Class FirstChild(Dad, Mom): ← Dad를 먼저 상속함

2. 왼쪽 부모 우선(리스트에 나열된 순서로 탐색)
3. 중복 방문 방지
ClassName.__mro__ 또는 ClassName.mro()를 입력하면 순서를 알 수 있음

ParentB.__init__()를 직접 적어도 되간 함
부모 클래스 이름을 직접 명시하는 건 좋지 않음

super()는 부모클래스를 호출하는 게 아님
MRO 순서에 따라서 다음 클래스를 호출함

호출 시작점 중요함
child가 인스턴스를 만듦(다른 인스턴스는 만들지 않음)
child의 super()가 호출
MRO 순서에 따라 parentA로 감
parentA에 super 있음
그 다음은 Parent B로 감
그 결과 child에 3개
만약 parent B의 값이 필요 없다면 parentA에있는 super 지우면 거기서 끊김.



class ParentA:
    def __init__(self):
        super().__init__()  # <- 이 줄이 주석 처리된 것이 이 예제의 핵심
        print(super())
        self.value_a = 'ParentA'

    def show_value(self):
        print(f'Value from ParentA: {self.value_a}')


class ParentB:
    def __init__(self):
        self.value_b = 'ParentB'

    def show_value(self):
        print(f'Value from ParentB: {self.value_b}')


class Child(ParentA, ParentB):
    def __init__(self):
        super().__init__()  # ParentA 클래스의 __init__ 메서드 호출
        # ParentB.__init__() # 직접 부모 클래스 이름을 적어도 됨
        self.value_c = 'Child'

    def show_value(self):
        super().show_value()  # ParentA 클래스의 show_value 메서드 호출
        print(f'Value from Child: {self.value_c}')

여기서 class ParentA의  super().__init__()는 누굴까?
답: 모른다.

 super().__init__()는 시작점이 중요함
