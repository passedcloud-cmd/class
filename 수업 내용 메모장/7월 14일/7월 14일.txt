Merge: 2가지
충돌이 있어날 수 있음

Git Branch의 장점
1. *독립*된 개발 환경을 형성하기 때문에 원본(master)에 대해 안전
실제 개발은 원본(master)가 아니라 branch에서 작업함.
원본엔 최종본만.

상용 중인 서비스에 발생한 에러를 해결하려면?
1. 브랜치를 통해 별도의 작업 공간을 만든다.
2. 브랜치에서 에러가 발생한 버전을 이전 버전으로 되돌리거나 삭제한다.
3. 브랜치는 완전하게 독립되어 있어서 작업 내용이 master브랜치에 아무런 영향을 미치지 못함.
4. 이후 에러가 해결됐다면? 그 내용을 master브랜치에 반영 가능

Master(main)브랜치의 의미 역할
기본 브랜치(Default Branch): 가장 최신 버전. 배포 가능한 안정적인 코드.

브랜치의 최종 목표는 병합

git switch: HEAD(우리가 보고 있는 위치)
git switch <다른 브랜치 이름>
git switch -c <브랜치 이름> 
 둘 다 최근 커밋으로 이동

<>는 안에 있는 값이 변할 수 있다는 표시딜 뿐 <>를 적으면 안됨

git switch -c <브랜치 이름><commit ID> 
과거 커밋이나 특정 커밋으로 이동

master 커밋은 브랜치로부터 합쳐질 때 생김

(13p)언제나 다음 커밋은 이전 커밋에 의존하고 있음.
화살표는 그 의존성의 방향을 나타냄
feature는 가운데 커밋에서 생성되었기에 화살표가 가운데를 향함

switch하기 전에 woring directory 파일이 모두 버전 관리가 되어 있는지 확인해야 함.
브런치를 이동하기 전에 완료된 작업은 버전을 찍고 나서 다른 브런치로 이동해야 함.
커밋을 찍었다는 가정 하에 독립적인 것임.
모든 파일이 git의 관리를 받는지 확인해야 함.
커밋은 진행 방향과 화살표 표기 방향이 다른 이유: 종속 관계를 나타내기 때문.

 git branch login 후 (login 브랜치 만듦)
 git branch 하면 *로 우리가 어디 있는지 알려줌
login은 아직 뻗어나가지 않음.
수정사항도 없었고 커밋도 쌓지 않았기 때문.

이제 head를 이동해야 함.
$ git switch login
하면 login으로 이동함. master 브런치로부터 다른 독립적. 

git log --oneline 하면 login 이후 master에서 나아간 커밋은 볼 수 없음
옵션을 붙여서 앞에 나간 모든 커밋을 볼 수 있음
git log --oneline --all  :  모든 커밋 볼 수 있음

login에서 변경 사항 만들고 커밋 쌓기

git log --oneline --all --graph  : 브랜치가 어디서 갈라졌는지 볼 수 있음.

git switch master 하면 다른 공간으로 이동

working directory의 내용도 HEAD가 가리키는 브랜치의 최신 커밋을 보여줌


병함 전 주의 사항!
병합 전 내가 어디있는지 확인해야 함
병합할려는 수신 브랜치를 작성하기 때문.
그리고 수신 브랜치와 병합 브랜치 모두 최신 상태여야 함.

Fast-forward merge
Merge 과정 없이 단순히 브랜치의 포인터가 앞으로 이동.
브랜치가 생기고 나서 master에 아무 변화가 없었다면,
역설적으로 브랜치쪽이 최근 버전이 됨.
그래서 master를 브랜치 쪽으로 끌어옴.

master에서 git merge hotfix 하면 땡겨짐

병합 완료된 hotfix 브랜치는 삭제
git branch -d hotfix


3-way merge
병합 대상인 두 커밋의 공통 조상 커밋을 봄.
그리고 새로운 버전이 생성되어 찍힘. ->머지 커밋이 생김

git merge hotfix 치면
VIM이 나옴

VIM 모드 2가지
1. 입력 모드(텍스트 입력)
2. 명령 모드(저장, 종료...) : Shif + :
	저장은 W, 종료는 Q

git branch -d hotfix



Merge Conflict
병합하려는 두 브랜치가 "동일한 파일의 동일한 부분"에서 변경된 후 병합 시 충돌이 일어남.

 git merge hotfix하면 충돌일어남
충돌된 분 수정하면 (master|MERGING) 상태
git add .
git status
git commit
