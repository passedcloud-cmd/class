디코딩 알고리즘
거대 언어 모델의 자동회귀 생성
EOS: 문장이 끝나는 걸 알려주는 토큰 [SEP]
EOS 토큰 생성 시 종료 혹은 사저에 정의된 토큰 수에 도달하면 종료


디코딩 알고리증
주어진 입력 x1~xL
p햇 확률분포로부터 xL+1을 생성하는 알고리즘
EOS를 만나거나 토큰 수가 너무 많으면 종료
거대 언어 모델이 확률 분포를 예측해줌 p햇
한 글자 한 글자를 MML이 만들고 다음으로 오는 글자를 LLM이 확률 분포로 예측
확률 분포에서 어떤 글자를 고르는지는 디코딩 알고리즘이 함

output은 토큰화된 입력+출력

argument를 어떻게 설정하느냐에 따라 동작하는 디코딩 알고리즘이 다름
디코딩 알고리즘은 여러 개 존재
디코딩 알고리즘을 작동시키게 하는 argument들이 있다

1) greedy decoding
가장 확률이 높은 다음 토큰을 선택
사용하기 쉬움
직후만 고려해서 최종 답이 최선이 아닐 수 있음

The dog has 0.36
The nice woman 0.2
전자가 더 좋은 선택이었는데 후자를 선택하게 됨

2) Beam search
확률이 높은 k개(beam size)의 후보를 동시에 고려
k개의 개수만큼 연산량이 늘어남. 비용 증가
k=4까지만 쓰는 게 좋음. 느려져서 잘 쓰지 않음

3) 샘플링
다양한 응답을 생성할 수 있는 여지가 생김
응답 품질이 감소할 수 있음
운이 나빠서 확률이 낮은 단어를 고름

4) 샘플링 with temperature
t가 1보다 낮으면 확률 분포가 샤프해짐
확률이 낮은 건 더 낮아지고 높은 건 더 높아짐
t=0이면 greedy decoding과 같아짐

t가 1보다 크면 확률 분포가 완만해짐 확률이 비슷해짐
다양한 답이 나올 수 있음

5) Top-K 샘플링
확률이 높은 k개의 토큰들 중에서만 랜덤하게 샘플링
가능성 낮은 단어는 버림
단점: 확률 분포의 모양에 상관없이 고정된 k개의 후보군을 고려함
k값이 유동적으로 바뀌면 좋겠음

6) Top-p 샘플링(Nucleus 샘플링)
현재 LLM이 사용하는 샘플링
누적 확률(P)에 집중하여 K를 자동으로 조정
(Top-p가 1이면 모든 후보군을 봄)
예) P=0.9로 누적되면 K는 그 값으로 사용
p=0.95일 때 사람과 유사한 결과

=>
같은 입력에 대해서도 출력할 때마다(디코딩할 때마다) 출력이 다름
디코딩 알고리즘 자체가 확률적이기 때문
