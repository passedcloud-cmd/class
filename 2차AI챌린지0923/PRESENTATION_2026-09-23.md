# 발표 정리 — 사진 속 글자를 읽고 4지선다 풀기 (2026-09-23)

> 7분 발표용 정리. 숫자는 모두 실제 제출·실험 기록에서 가져왔다.
> "내부 검증"은 학습 데이터에서 떼어 둔 1,074문항, "Kaggle"은 Public 리더보드(테스트의 절반, 3,357문항) 점수다.

**우리 팀 한 줄:** 한 번에 한 가지만 바꿔서 무엇이 점수를 올리는지 분리했다. 그 결과 **이미지 해상도와 모델 크기가 진짜 레버**였고, 그 뒤로는 **서로 다르게 틀리는 모델들의 투표**로 올렸다. **0.70 → 0.969**.

---

## 1. 문제와 데이터 (30초)

- 사진 한 장 + 한국어 질문 + 보기 4개 → 정답 보기 하나 고르기. 간판·메뉴·가격표·안내문처럼 **사진 속 글자를 읽어야 푸는 문제**가 대부분이다.
- 학습용 6,714문항(정답 있음), 테스트 6,714문항. 사진은 대부분 720×960 세로 사진이다.
- 제공 베이스라인 노트북: **0.70241**.

## 2. 접근 방법과 근거 (1분)

- **공통 출발점 하나를 만들고, 그 위에서 한 번에 한 축만 바꿔 비교했다.** 두 가지를 동시에 바꾸면 무엇 때문에 올랐는지 알 수 없다.
- **공통 출발점:** Qwen3-VL 4B 모델을 4비트로 올리고 얇은 추가층(LoRA)만 1회 학습.
  내부 검증 83.71% → **90.41%**(+6.70%p), Kaggle **0.89037**. 16GB 그래픽카드 한 장에서 43분.
- **공정한 비교:** 학습 데이터를 학습용 4,297 / 내부 검증 1,074 / 최종 확인용 1,343으로 고정해 나눴다(같은 사진은 한쪽에만).
- **병렬 실행:** 축 하나씩을 원클릭 실험 패키지로 만들어 팀원 4명이 각자 PC(RTX 5060 Ti 16GB)에서 동시에 돌렸다. 큰 모델은 Colab A100.
- **판정 기준:** 두 제출의 차이가 **우연 폭**을 넘을 때만 "효과 있음"으로 본다.
  두 제출이 n문항에서 답이 다르면, 운만으로도 약 ±2·√(n/2)문항 차이가 날 수 있다(95%).
- **규칙은 결과를 보기 전에 정해서 코드로 커밋**했다. 점수를 본 뒤 규칙을 고르면 Public에만 맞춘 결과가 된다.

## 3. 1단계 — 독립 실험 축 3개: 모델 크기 · 추론 해상도 · OCR (1분 30초)

같은 출발점에서 한 축씩만 바꿨다.

| 축 | 바꾼 것 | 내부 검증 | Kaggle | 판정 |
|---|---|---|---|---|
| **추론 해상도** | 사진을 512² → 768²로 크게 넣음(학습은 그대로) | 90.41% → **93.58%** (+3.17%p, 95% 구간 [+1.68, +4.66]) | 0.89037 → **0.93029** (+3.99%p) | **채택. 가장 큰 레버** |
| **모델 크기** | 4B → 8B (같은 방식으로 학습) | 90.41% → 91.99% (+1.58%p, 구간 하한 0.00으로 경계) | 0.89037 → **0.91271** (+2.23%p) | **채택** |
| **OCR** | 글자 인식 결과(PaddleOCR)를 질문과 함께 넣음 | 90.41% → 90.88% (+0.47%p, 구간 [−0.47, +1.49]가 0 포함) | 제출 안 함 | **탈락** |

- 해상도 효과는 **가격 문항**에서 특히 컸다(77.27% → 89.09%).
- 학습 전 모델끼리 400문항으로 미리 본 크기 효과: 4B 338 → 8B 351 → 32B 368문항.

**두 레버는 서로 독립이었다** — 2×2를 모두 제출해 확인했다(Kaggle).

| | 추론 512² | 추론 768² | 해상도 효과 |
|---|---:|---:|---:|
| **4B** | 0.89037 | 0.93029 | **+3.99%p** |
| **8B** | 0.91271 | **0.95233** | **+3.96%p** |
| **크기 효과** | **+2.23%p** | **+2.20%p** | 겹침 −0.03%p |

→ 두 효과가 거의 그대로 더해진다(누적 +6.2%p). 그래서 다음 단계에서도 축을 따로 재고 합칠 수 있었다.

## 4. 2단계 — OCR 탈락 후: 모델 크기 · 학습 해상도 · 추론 해상도 (1분)

| 축 | 바꾼 것 | 결과 | 판정 |
|---|---|---|---|
| **추론 해상도 더 올리기** | 4B, 768² → 1024² | Kaggle 0.93029 → **0.93863** (+28문항) | 효과 있음(작아짐). 1024²는 원본 크기(720×960)에 가깝다 |
| | 8B, 768² → 1024² | 내부 검증 +2문항 | 효과 없음 |
| **학습 해상도** | 4B를 768²로 다시 학습(추론 768² 동일) | 내부 +3문항, Kaggle 0.93029 → 0.93238 (+7문항, 우연 폭 ±16 안) | **효과 없음** |
| **모델 크기** | 32B, 1024²로 학습·추론(전체 데이터) | Kaggle **0.95621** | 기대(0.968) 미달 |
| | 같은 방식의 8B | Kaggle **0.95680** | **8B = 32B** |

**왜 학습 해상도는 효과가 없나?** 추가층(LoRA)은 모델의 "언어 부분"에만 붙어 있고, 사진을 읽는 "시각 부분"은 학습하지 않는다. 그래서 어떤 해상도로 학습하든 같은 사진에서 나오는 시각 정보는 같다. **해상도는 추론할 때만 효과가 있다.**

**왜 32B가 기대에 못 미쳤나?** 모델이 클수록 추가 학습으로 얻는 몫이 줄었다.

| 모델 | 학습 전 → 학습 후 (내부 검증) | 학습 효과 |
|---|---|---|
| 4B | 899 → 971문항 | **+72** |
| 8B | 954 → 988문항 | **+34** |
| 32B | 학습 중 처음 본 1,037문항 기준 | **≈ 0** (−0.29%p) |

→ 큰 모델은 이미 이 문제 형식을 안다. **더 큰 모델 하나로는 한계** → 방향을 바꿨다.

## 5. 3단계 — 앙상블 축 (2분)

**아이디어:** 같은 모델을 키우는 대신, **다르게 틀리는 모델**을 모아 투표한다. 그리고 **헷갈리는 문항에만** 계산을 몰아준다.

### 5-1. 점수 계단 (Kaggle, 3,357문항 중 맞힌 수)

| 단계 | 무엇을 더했나 | Kaggle | 직전 대비 |
|---|---|---:|---:|
| ① 32B 단독 | 1024² 학습·추론 | 0.95621 (3,210) | |
| ② 보기 순서 바꿔 두 번 풀기 | 보기 순서를 abcd·cdab로 바꿔 채점하고 평균 | 0.96067 (3,225) | **+15** (우연 폭 ±12 밖) |
| ③ 8B 답을 한 표로 | 32B 확률 + 8B가 고른 답에 가산점 | 0.96276 (3,232) | **+22** (①대비, ±18 밖) |
| ④ ②+③ | | 0.96336 (3,234) | +2 (②③이 같은 문항을 고침) |
| ⑤ **다른 회사 모델 추가** | Gemma 4 31B(학습 없이 그대로)까지 3자 다수결 | 0.96514 (3,240) | +6 |
| ⑥ 4자 다수결 | 같은 방식으로 학습한 새 8B 추가 | 0.96723 (3,247) | +7 |
| ⑦ **헷갈리는 문항만 다시 풀기** | 434문항만 32B·Gemma로 보기 순서·해상도 4가지씩 다시 채점 → 다수결 | 0.96723 (3,247) | +7 (⑤대비) |
| ⑧ **5자 투표** | ⑦ + Qwen3.8 27B + 새 8B | **0.96872 (3,252)** | +5 |

- **단계 하나하나(+1~+7)는 우연 폭 안이다. 누적은 확실하다:** 32B 단독 대비 **+42문항**(우연 폭 ±18).

**헷갈리는 문항에서 32B·Gemma 외에 누구의 표를 더할까?**

| 더한 표 | Kaggle |
|---|---:|
| Qwen3.8 27B (학습 없음) | 0.96633 (3,244) |
| 기존 8B (768² 추론) | 0.96723 (3,247) |
| 새 8B (1024² 학습·추론) | 0.96753 (3,248) |
| 기존 8B + Qwen3.8 (4표) | 0.96723 (3,247) |
| **셋 다 (5표)** | **0.96872 (3,252)** |

→ 한 명만 고르면 누구든 비슷하다(차이 4문항, 우연 폭 ±13 안). **셋을 다 넣은 5표가 가장 높았다.**
- 투표 방식: 확률 평균(0.96484)과 다수결(0.96514)은 차이가 없었다. Gemma가 틀린 답에도 99% 확신을 주는 경우가 많아(오답 38건 중 27건) 다수결을 택했다.

### 5-2. 왜 Gemma였나 — "다르게 틀린다"

- Gemma는 학습 없이도 내부 검증 **96.46%**로 우리 모델 중 최고였다. 하지만 Kaggle 단독 점수는 0.95084로 32B보다 약간 낮았다(우연 폭 안).
- 32B와 답이 다른 테스트 문항이 **350개(5.2%)**. 둘 다 틀린 문항은 적고, 대부분 라벨 문제였다.
  → 실력은 비슷한데 **틀리는 곳이 다르다** = 투표 멤버로 이상적.

### 5-3. 왜 "헷갈리는 문항만"인가 — 확신도 ≠ 안정성

- 헷갈리는 문항 434개 = 모델끼리 답이 갈림 ∪ 32B가 1·2등을 거의 못 가름 ∪ 보기 순서만 바꿔도 32B 답이 바뀜. 결과를 보기 전에 목록을 고정했다.
- Gemma는 이 문항 대부분에 **99% 이상 확신**하면서도, 보기 순서·해상도만 바꾸면 **답이 30~42% 바뀌었다**. 32B도 약 25%가 바뀌었다.
- 여러 조건의 평균을 쓰면 두 모델이 갈린 문항이 **350 → 247**로 줄었다.
- 전체를 다시 푸는 대신 474문항(검사용 40 포함)만 다시 풀어서 A100 몇 분이면 끝난다. 16기 1회차 1등 풀이의 "불확실한 문항만 다시 풀기"를 참고했다.

## 6. 3일 일정과 시행착오 (발표 중간이나 6절 끝에 녹이기)

| 날짜 | 한 일 |
|---|---|
| 9/21 | 데이터 점검·고정 분할, 공통 출발점 학습(Kaggle 0.89037), 팀원용 원클릭 패키지 |
| 9/22 | 1단계 축 병렬 실행 → 해상도·크기 채택, OCR 탈락 → 2×2 완성(0.95233) → 32B 학습 시작 |
| 9/23 새벽 | 32B 제출(0.95621) → 앙상블 → 헷갈리는 문항 재채점 → 5자 투표(0.96872) |

**시행착오 → 원인 → 다음 선택**

1. **조용한 버그:** "768²로 학습" 설정을 학습 코드가 무시하고 512²로 돌았다. 팀원 두 명이 각자 약 1시간씩 돌린 학습이 기존 모델의 **완전한 복제**가 됐다(모델 파일 해시가 같고, Kaggle 점수도 소수점까지 같음).
   → 코드를 고치고, 학습 시작 때 실제 해상도를 화면에 찍게 하고, 모델 해시를 비교하는 검사를 넣었다.
2. **32B 기대 미달(0.968 기대 → 0.95621):** 원인은 큰 모델의 학습 효과 소멸(4절).
   → "더 큰 모델" 대신 "다른 모델 투표"로 전환 → +42문항.
3. **내부 검증과 Kaggle이 두 번 어긋났다:** 투표 멤버를 내부 검증으로 고르면 Kaggle에서 반대로 나왔다.
   → 규칙을 결과 전에 고정하고, 우연 폭을 넘을 때만 최종을 바꾼다.
4. **안 된 것들(정직하게):** OCR, 학습 해상도, 8B 1024² 추론, 사진을 잘라 확대하기·타일링, 4B에서의 보기 순서 평균, 32B 학습.

## 7. 결과와 해석 (1분)

**최고 점수 흐름:** 0.70241(베이스라인) → 0.89037(4B 학습) → 0.93029(해상도) → 0.95233(8B) → 0.95621(32B) → 0.96276(8B 한 표) → 0.96514(Gemma 투표) → **0.96872(5자 투표)**

**최종 제출 2개**

| | Kaggle | 내용 | Kaggle 파일 |
|---|---:|---|---|
| 1순위 | **0.96872** | 헷갈리는 문항 5자 투표 | `B3_maj_S4_G4_M_Q_E.csv` |
| 2순위(보험) | 0.96753 | 헷갈리는 문항 4자 투표(판정 멤버만 새 8B) | `C1_maj_S4_G4_E.csv` |

두 파일은 59문항이 달라서, Public에서만 운이 좋았을 경우를 서로 보완한다.

**남은 오답의 정체:** 32B가 학습한 뒤에도 정답과 다르게 답한 내부 검증 문항 12개를 사진으로 확인했다. **11개가 라벨 오류·정답이 둘·모호한 문제**였다.
라벨 문제를 1.5~2%로 잡으면, 우리 점수(오답 3.1%)는 도달 가능한 천장 근처다.

**배운 것 세 줄**
1. 글자 읽기 문제에서는 **추론 해상도**가 모델 크기보다 센 레버다(+4.0%p vs +2.2%p). 학습 해상도는 상관없다.
2. 모델을 키우면 추가 학습의 몫이 사라진다(+72 → +34 → 0). 그다음은 **다르게 틀리는 모델의 투표**다.
3. 모델의 확신은 안정성이 아니다. **헷갈리는 문항만 조건을 바꿔 다시 풀면** 적은 계산으로 흔들린 답을 정리할 수 있다.

## 부록 A. 예상 질문과 답

- **Q. Kaggle 점수에 과적합한 것 아닌가?**
  A. 투표 규칙은 결과를 보기 전에 정해 커밋했다(커밋 시각이 증거). 단계별 차이는 우연 폭 안이라고 스스로 밝히고 있고, 확실하다고 말하는 것은 누적 +42문항뿐이다. 최종 2개도 서로 다른 조합으로 골랐다.
- **Q. 왜 OCR이 안 됐나?**
  A. 내부 검증 +0.47%p였고 구간이 0을 포함해서 채택 근거가 없었다. 해상도를 올리면 모델이 직접 글자를 읽기 때문에 OCR 정보가 겹쳤을 가능성이 있다(추정).
- **Q. 32B 학습 설정(학습률·에폭)을 바꿨으면 되지 않았나?**
  A. 가능성은 있다. 다만 4B → 8B → 32B로 학습 효과가 일관되게 줄어드는 추세라 우선순위를 낮췄고, 같은 시간을 투표 멤버에 썼다.
- **Q. 내부 검증을 믿을 수 있나?**
  A. 같은 사진이 학습과 검증에 동시에 들어가지 않게 나눴다. 내부 검증과 Kaggle을 둘 다 잰 여섯 모델(4B 네 가지, 8B 두 가지)의 **순서가 Kaggle에서도 똑같았다.** 점수는 Kaggle이 0.2~1.4%p 낮았다. 단, 전체 데이터로 학습한 32B·새 8B는 내부 검증을 쓸 수 없어 Kaggle로만 판단했다. 학습 없이 쓴 Gemma는 내부 검증 최고였지만 Kaggle에서는 1.4%p 낮아, 예외로 본다.
- **Q. 1등(9/22 기준 0.97438)과의 차이는?**
  A. 약 20문항. 남은 오답의 상당수가 라벨 문제라 차이를 가를 신호가 적다. 추론 모드와 다른 계열 모델이 남은 후보다.
