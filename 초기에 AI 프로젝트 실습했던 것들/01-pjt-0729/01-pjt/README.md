## 구현한 기능

### 1. 책 제목 리스트 추출

JSON 파일을 읽은 뒤 `item` 리스트를 순회하면서 각 도서의 `title` 값을 추출했다.

배운 점은 JSON 파일을 열었을 때 바로 리스트가 나오는 것이 아니라, 최상위 구조가 딕셔너리일 수 있다는 점이었다.

```
data = json.load(file)

```
이후 실제 책 목록은 data['item']에 들어 있었다.


### 2. 도서 평균 가격 계산


각 도서의 priceSales 값을 리스트에 저장하고, sum()과 len()을 이용해 평균 가격을 계산했다.
이 과정에서 빈 리스트일 경우 나누기 오류가 발생할 수 있다는 점을 알게 되었다.

```
average_price = sum(book_prices) / len(book_prices)
```

또한 가격 데이터가 문자열일 가능성도 고려해야 하므로 필요하면 int()로 형 변환해야 한다는 점을 배웠다.



### 3. 도서별 작가 딕셔너리 생성

도서 제목을 key로, 작가를 value로 하는 딕셔너리를 만들었다.


```
book_authors[title] = author
```

이 기능을 구현하면서 딕셔너리의 key가 중복되면 나중 값으로 덮어써진다는 점을 다시 확인했다.


### 4. 정가 범위 분류


priceStandard 값을 기준으로 도서를 가격 범위별로 분류했다.
예시 범위는 다음과 같이 나누었다.
1만원 미만
1만원 이상 2만원 미만
2만원 이상
처음에는 결과가 {}로 출력되어 왜 데이터가 들어가지 않는지 확인했는데, 원인은 append 코드가 빠져 있거나 출력 위치가 반복문 안에 있었기 때문이었다.
이 문제를 통해 딕셔너리 초기화 위치와 출력 위치가 중요하다는 것을 알게 되었다.


### 5. 어린이 도서가 아닌 책 필터링
카테고리명에 '어린이'가 포함되지 않은 도서만 필터링했다.

```
if '어린이' not in category:
    non_children_books.append(book)

```


처음에는 books라는 변수를 사용했지만 정의되어 있지 않아 오류가 발생했다. 이후 실제 데이터가 data['item']에 있다는 것을 확인하고 수정했다.


### 6. 출판사별 도서 수 집계
각 도서의 publisher 값을 기준으로 출판사별 도서 수를 계산했다.
```
if publisher not in publisher_counts:
    publisher_counts[publisher] = 0
```

publisher_counts[publisher] += 1
이 기능을 통해 딕셔너리에 key가 없을 때 먼저 초기화해야 한다는 점을 익혔다.

### 7. 카테고리별 도서 수와 평균 가격 계산
카테고리별로 도서 수와 판매가 합계를 저장한 뒤, 마지막에 평균 가격을 계산했다.
```
category_stats[category] = {
    'count': 0,
    'total_price': 0
}
```

출력할 때 평균 가격을 소수점 둘째 자리까지 출력하기 위해 포맷팅을 사용했다.
```
{average_price:.2f}
```

이 과정에서 출력 형식을 요구사항에 맞추는 것도 중요하다는 것을 느꼈다.

### 8. 출판일 기준 최신 도서 10개 추출

pubDate 값을 datetime.strptime()으로 날짜 객체로 변환한 뒤, 최신순으로 정렬했다.

```
datetime.strptime(book['pubDate'], '%Y-%m-%d')
```

문자열 날짜도 형식이 일정하면 정렬할 수 있지만, 날짜 데이터는 날짜 객체로 변환해서 
비교하는 것이 더 안전하다는 점을 배웠다.


### 9. 할인율 상위 5개 도서 추출

정가와 판매가를 이용해 할인율을 계산했다.
```
discount_rate = (priceStandard - priceSales) / priceStandard * 100
```

정가가 0일 경우 0으로 나누는 오류가 발생할 수 있기 때문에 예외 처리가 필요했다.

### 10. 월별 도서 평균 가격 계산

books_2000.json 데이터를 읽고, 출판일 기준으로 월을 추출하여 월별 평균 가격을 계산했다.
```
month = date.month
```
월별로 다음 정보를 저장했다.
총 가격
도서 수
평균 가격
출력 순서를 1월부터 12월까지 정렬하기 위해 sorted()를 사용했다.

```
for month, stats in sorted(monthly_stats.items()):
```
이 기능을 구현하면서 들여쓰기 위치가 매우 중요하다는 것을 다시 느꼈다.

특히 평균 계산은 반복문 안에서 하는 것이 아니라, 모든 데이터 누적이 끝난 뒤에 해야 했다.

### 11. 카테고리별 JSON 파일 생성

categoryId와 categoryName을 기준으로 도서를 분류한 뒤, category_books.json 파일을 생성했다.
각 도서 정보에는 다음 값을 포함했다.
제목
저자
출판사
출판일
ISBN
가격
JSON 파일을 저장할 때는 한글이 깨지지 않도록 ensure_ascii=False를 사용했다.

```
json.dump(data, file, ensure_ascii=False, indent=4)

```

### 12. 시리즈 정보 병합

data/series_items 디렉토리 안의 여러 폴더와 JSON 파일을 순회하면서 시리즈별로 데이터를 병합했다.
처음에는 각 JSON 파일 안에 seriesId, seriesName이 있을 것이라고 생각했지만 실제 데이터 구조는 달랐다.
실제 JSON 파일은 책 한 권의 정보가 바로 딕셔너리 형태로 들어 있었고, 시리즈 구분은 상위 폴더명이 담당하고 있었다.
따라서 다음과 같이 처리했다.
json_path.parent.name을 이용해 시리즈 ID 추출
각 JSON 파일을 책 한 권으로 보고 리스트에 추가
같은 폴더에 있는 책들을 하나의 시리즈로 병합
최종 결과를 series.json으로 저장
이 과정에서 파일 구조를 추측하지 말고 직접 print(type(data)), print(data.keys())로 확인하는 것이 중요하다는 것을 배웠다.



## 프로젝트를 하며 새롭게 배운 점



### 1. JSON 구조 확인의 중요성

이번 프로젝트에서 가장 많이 겪은 오류는 JSON 구조를 잘못 예상해서 발생한 오류였다.
예를 들어 다음과 같은 오류가 있었다.

NameError: name 'data' is not defined
KeyError: 'seriesId'
TypeError: string indices must be integers

파일이 존재하지 않는 오류
처음에는 무조건 data['item']에 데이터가 있을 것이라고 생각했지만, 파일마다 구조가 달랐다.

그래서 데이터를 다룰 때는 먼저 구조를 확인해야 한다는 점을 배웠다.

```
print(type(data))
print(data.keys())
```


### 2. pathlib 사용법
파일 경로를 다룰 때 문자열만 사용하는 것이 아니라 Path 클래스를 사용할 수 있다는 것을 배웠다.

```
file_path = Path('data/books_500.json')
```

파일 존재 여부도 간단하게 확인할 수 있었다.

```
file_path.exists()
```

또한 하위 폴더의 모든 JSON 파일을 찾을 때 rglob()를 사용할 수 있었다.
```
base_path.rglob('*.json')
```


### 3. 딕셔너리 누적 패턴

출판사별 도서 수, 카테고리별 통계, 월별 평균 가격, 시리즈 병합 기능에서 공통적으로 딕셔너리를 활용했다.
공통 패턴은 다음과 같았다.

```
if key not in dictionary:
    dictionary[key] = 초기값
```

dictionary[key]에 값 누적

처음에는 이 구조가 헷갈렸지만, 여러 문제에서 반복해서 사용하면서 익숙해졌다.


### 4. 날짜 데이터 처리

datetime.strptime()을 사용해 문자열 날짜를 날짜 객체로 바꾸는 방법을 배웠다.

```
datetime.strptime(book['pubDate'], '%Y-%m-%d')
```
이를 통해 최신 도서 정렬, 월별 분류 같은 기능을 구현할 수 있었다.


### 5. 출력 형식 맞추기

문제를 해결하는 것뿐만 아니라, 출력 형식도 요구사항에 맞춰야 했다.
예를 들어 평균 가격을 소수점 둘째 자리까지 출력할 때는 다음과 같이 작성했다.

```
{average_price:.2f}
```

단순히 값만 계산하는 것이 아니라, 사용자가 보기 좋은 형태로 출력하는 것도 중요하다고 느꼈다.

## 1. 프로젝트 주제

이번 프로젝트는 도서 정보가 담긴 JSON 파일을 Python으로 읽고, 파일 시스템과 데이터 가공 로직을 활용해 다양한 도서 통계를 생성하는 프로젝트이다.

주요 작업은 도서 제목 추출, 평균 가격 계산, 리뷰 순위 분석, 작가 정보 정리, 정가 범위 분류, 카테고리 및 출판사별 집계, 최신 도서 및 할인율 높은 도서 추출, 월별 평균 가격 계산, 카테고리별 JSON 파일 생성, 시리즈 도서 정보 병합이었다.

또한 일부 작업에서는 생성형 AI를 활용해 데이터 요약, 인사이트 도출, 가상 도서 정보 생성 가능성까지 확장하는 것을 목표로 했다.

## 2. 프로젝트 목적

이 프로젝트의 목적은 파일 입출력과 JSON 데이터 가공에 익숙해지는 것이다.

구체적으로는 `pathlib.Path`를 사용해 파일과 디렉토리의 존재 여부를 확인하고, `json` 라이브러리로 JSON 파일을 Python 자료구조로 변환한 뒤, 리스트와 딕셔너리를 활용해 필요한 정보를 추출·집계·정렬하는 연습을 했다.

또한 단순히 데이터를 출력하는 것을 넘어, 조건에 따라 데이터를 분류하고 새로운 JSON 파일로 저장하면서 실제 데이터 처리 흐름을 경험하는 것을 목표로 했다.

## 4. 협업하면서 어려웠던 점과 개선할 점

### 어려웠던 점

#### 1) JSON 구조 파악

처음에는 모든 JSON 파일이 `{ "item": [...] }` 형태라고 생각하고 `data['item']`을 사용했다. 하지만 실제로는 최상위가 리스트 `[...]`인 파일도 있었고, 이 경우 `data['item']`을 사용하면 오류가 발생했다.

이를 통해 코드를 작성하기 전에 먼저 `print(type(data))`로 JSON의 최상위 구조가 `dict`인지 `list`인지 확인하는 과정이 필요하다는 것을 알게 되었다.

여유가 있다면 직접 JSON 파일을 열어 데이터 구조를 직접 살펴보는 게 가장 좋다.

#### 2) JSON key와 Python 변수의 차이

도서별 작가 정보를 정리할 때 `book_authors[title] = author`처럼 작성했지만, `title`과 `author` 변수를 따로 정의하지 않아 `NameError`가 발생했다.

JSON 파일 안에 `"author"`라는 key가 있어도 Python 코드에서 `author`라는 변수가 자동으로 생기는 것은 아니었다.

반드시 `author = item['author']`처럼 딕셔너리에서 값을 꺼내 변수에 저장해야 한다는 점을 배웠다.

#### 3) 검증용 출력 혼동

월별 도서 평균 가격을 계산할 때 검증용으로 출력한 `2024-10 158` 같은 결과가 최종 출력과 함께 나타났다.

처음에는 평균 계산 코드가 잘못된 줄 알았지만, 실제 문제는 검증용 출력 코드가 남아 있었기 때문이었다.

채점이나 결과 확인이 필요한 코드에서는 디버깅용 출력과 최종 출력이 섞이지 않도록 주의해야 한다.

검증을 하고 난 뒤 혼동을 피하기 위해 검증용 코드는 `ctrl + /'`로 주석처리 해야 한다.

#### 4) 딕셔너리 key 이름 통일

월별 가격 합계를 계산할 때 처음에는 `total_price`라는 key를 만들었지만, 값을 더할 때는 `total`이라는 key를 사용했다. 이처럼 key 이름이 일관되지 않으면 `KeyError`가 발생하거나 의도한 계산이 되지 않는다.

딕셔너리 구조를 설계할 때는 사용할 key 이름을 먼저 정하고, 코드 전체에서 같은 이름을 유지해야 하므로 주의해야 한다.

#### 5) 원하는 JSON 구조와 실제 결과 차이

처음 시리즈 도서 정보를 병합했을 때 결과가 리스트 형태로 생성되었다. 하지만 원하는 구조는 `seriesId`를 key로 갖는 딕셔너리 형태였다.

또한 폴더명을 시리즈 이름처럼 사용했더니 실제 시리즈명이 아니라 `"1036021"` 같은 ID가 `seriesName`에 들어가는 문제가 있었다. 

책 데이터 내부의 `seriesInfo.seriesId`, `seriesInfo.seriesName`을 사용해야 한다는 것을 확인했다.

#### 6) 파일 경로 기준

코드를 실행할 땐 해당 코드 파일이 존재하는 경로에서 실행해야 한다.

그렇지 않으면 오류가 발생하거나 참고한 데이터 파일의 경로를 찾을 수 없다.

코드를 실행하기 전엔 항상 코드가 실행되는 위치와 실제 파일 위치가 일치하는지 확인해야 한다.

#### 7) 원격 저장소(repository&project) 충돌

원격 저장소에 commit을 push할 때 충돌이 발생하여 merge를 하지 못했다.

READ.me가 작성되어 commit이 1개 쌓인 파일을 clone 혹은 pull 하지 않고 내 로컬에서 작업했기 때문에 누적된 commit이 일치하지 않았기 때문이었다.

또한 master의 관리에 있는 파일을 수정했기 때문에 merge 시도 시 기존 master 파일과 내가 push를 시도한 파일 일부가 일치하지 않아 충돌이 일어났다.

merge 충돌을 피하기 위해서는 branch 관리에 주의를 기울어야 한다. 

  예방법: 파일을 clone 받으면 가장 먼저 branch를 생성한다. 그리고 각자 어떤 파일에서 작업을 진행할 것인지 팀원들과 미리 정한 후, 공용 파일은 함부로 수정하지 않는다. 공용 파일을 수정해야 할 일이 생기면 팀원들에게 수정 사항을 알린다. 

### 개선할 점

- JSON 파일을 읽은 직후 `type(data)`와 일부 샘플 데이터를 확인하는 습관을 들인다.
- 딕셔너리 key 이름을 정리한 뒤 코드 전체에서 일관되게 사용한다.
- 검증용 출력 코드는 최종 제출 전 주석 처리하거나 삭제한다.
- 같은 기능을 반복 구현할 때 공통 패턴을 함수로 분리해 중복을 줄인다.
- 시리즈 병합처럼 중복 데이터가 있을 수 있는 작업에서는 `isbn`, `isbn13`, `itemId` 등 고유 식별자를 기준으로 검증한다.
- 파일을 clone 받으면 가장 먼저 branch를 생성하고 이동한다.
- 시작 전에 팀원들과 논의하여 각자 어떤 파일에서 어떤 작업을 진행할 것인지 정하고, master 관리 하에 있는 파일을 수정할 땐 미리 알린다.
- README나 주석에 “어떤 파일을 읽고, 어떤 결과 파일을 생성하는지”를 기록을 남긴다.

## 5. 새롭게 배운 것

### 이론적으로 배운 것

#### 1) JSON 데이터와 Python 자료구조의 관계

JSON 파일을 `json.load()`로 읽으면 JSON 구조에 따라 Python의 `dict` 또는 `list`로 변환된다.

- JSON 최상위가 `{}`이면 Python에서는 `dict`
- JSON 최상위가 `[]`이면 Python에서는 `list`

따라서 데이터를 순회할 때 항상 `data['item']`을 쓰는 것이 아니라, 실제 구조에 따라 `data` 또는 `data['item']`을 선택해야 한다.

#### 2) 딕셔너리를 이용한 집계 방식

출판사별 도서 수, 카테고리별 도서 수와 평균 가격, 월별 평균 가격을 계산하면서 딕셔너리를 이용한 집계 패턴을 익혔다.

예를 들어 처음 등장한 key는 초기값을 만들고, 이미 존재하는 key는 값을 누적하는 방식이다.

```python
if key not in stats:
    stats[key] = {'count': 0, 'total_price': 0}

stats[key]['count'] += 1
stats[key]['total_price'] += price
```

#### 3) 정렬과 key 함수

출판일 기준 최신 도서 10개, 할인율이 높은 도서 5개를 추출하면서 `sorted()` 함수의 `key` 매개변수와 `reverse=True` 사용법을 익혔다.

특히 할인율처럼 계산이 필요한 값은 별도의 함수를 만들고, 그 함수를 `key`로 전달할 수 있다는 것을 배웠다.

#### 4) 날짜 문자열 처리

`pubDate`가 `"YYYY-MM-DD"` 형식일 때 월별 분류를 위해 문자열 슬라이싱을 사용할 수 있었다.

```python
month = int(book['pubDate'][5:7])
```

이를 통해 날짜 데이터를 단순 문자열로도 일정 부분 처리할 수 있지만, 더 복잡한 날짜 처리가 필요하면 `datetime`을 사용할 수 있다는 점도 알게 되었다.

#### 5) 파일과 디렉토리 처리

`pathlib.Path`를 사용해 파일 존재 여부를 확인하고, 디렉토리 내부의 JSON 파일을 순회하는 방법을 배웠다.

- `Path.exists()` : 파일 또는 디렉토리 존재 여부 확인
- `Path.open()` : 파일 열기
- `Path.rglob('*.json')` : 하위 폴더까지 포함해 JSON 파일 검색
- `Path.cwd()` : 현재 작업 폴더 확인

#### 6) 새로운 JSON 파일 생성

가공한 데이터를 `json.dump()`로 다시 JSON 파일로 저장하는 방법을 익혔다.

```python
json.dump(data, file, ensure_ascii=False, indent=4)
```

`ensure_ascii=False`를 사용하면 한글이 깨지지 않고 저장되고, `indent=4`를 사용하면 사람이 읽기 좋은 형태로 저장된다는 것을 배웠다.

### 이론 외적으로 배운 것

#### 1) 오류 메시지를 읽고 원인을 좁히는 방법

NameError, key 오류, 파일 경로 오류 등을 겪으면서 오류 메시지의 위치와 변수명을 확인하는 것이 중요하다는 것을 배웠다.

단순히 “코드가 안 된다”가 아니라, 어느 줄에서 어떤 이름이 정의되지 않았는지 확인하면 문제 해결이 훨씬 빨라졌다.

#### 2) 작은 단위로 검증하는 습관

전체 기능을 한 번에 완성하려고 하기보다, 파일이 잘 열리는지, 데이터 타입이 무엇인지, 반복문이 원하는 항목을 순회하는지, 최종 출력 형식이 맞는지 작은 단위로 확인하는 것이 중요했다.

#### 3) 출력 결과를 요구사항과 맞추는 중요성

기능이 동작하더라도 출력 형식이 요구사항과 다를 수 있다. 특히 리스트를 그대로 출력하면 한 줄이 너무 길어지므로, 필요할 때는 반복문으로 보기 좋게 출력해야 한다.

#### 4) 데이터 원본을 보존하는 태도

시리즈 정보를 병합할 때 원본 JSON의 key-value 쌍이 바뀌지 않아야 한다는 점을 확인했다. 가공 과정에서 원본 값을 임의로 수정하지 않고, 필요한 경우 `book.copy()`처럼 복사본을 저장하는 방식도 고려해야 한다.

#### 5) 질문을 구체화하는 방법

처음에는 “코드를 어떻게 짜야 할까요?”처럼 넓게 질문했지만, 작업을 진행하면서 “어떤 변수에서 오류가 나는지”, “원하는 출력 형식이 무엇인지”, “JSON 구조가 리스트인지 딕셔너리인지”를 함께 확인해야 더 정확한 해결이 가능하다는 것을 배웠다.
